# 客户服务首版：同事联调清单

更新：2026-09-29。功能未发布；不要把构建产物直接投生产或打开开关。

## 已有本地实现

- H5 有效登录→5分钟只读委托票据→agent专用身份；请求头传递，不存凭据到历史。
- 公开店铺咨询、本人订单/售后查询及专用卡片，登录问题回填、选店、语音摘要。
- 查询监控：customer_service_logs，按操作/结果码聚合，面板新增客户服务区。
- Node签发/Python验签互通、模块与受控HTTP测试；真实浏览器使用拦截响应验证选店、登录返回、金额、退款状态、退出清理。未冒充真实商家测试。

## 同事环境就绪后提供

1. 商家服务测试地址、可信TLS/内网连接方式、接口文档、店铺编号映射。
2. 两个独立测试客户与专用订单；覆盖待支付、制作/配送、退款待审/处理中/成功/拒绝。
3. 店铺规则样例，使用 shop-knowledge-template.json；缺字段明确标记未知。
4. 核对现有退款字段是否代表完整售后，是否有部分退款、多个售后单或支付渠道延迟。

## 接入配置（只用占位值）

H5服务端：CUSTOMER_SERVICE_ENABLED=false，独立 AUTH_SECRET，CUSTOMER_SERVICE_SECRET（随机高熵、至少32字节）。
agent：CUSTOMER_SERVICE_ENABLED=false，CUSTOMER_SERVICE_SECRET 与 H5 一致，CUSTOMER_SERVICE_BASE_URL=https://可信业务入口/api/customer-service。
H5构建：VITE_CUSTOMER_SERVICE_ENABLED=false。按测试环境灰度同时开启服务端与前端；只改一个会造成换票或查询失败。

票据禁止走不可信HTTP；目前线上公网H5还是HTTP，客户端自身传输保护也需在私人业务开放前解决。不得关闭证书校验作为替代方案。

## 发布前必须完成

- 真实数据库验证 init_db 新监控表与聚合SQL；备份旧库/代码/镜像/静态资源。
- 服务端真实签名、过期、混用账号、A查B订单、已注销用户、上游5xx测试。
- 对照商家后台核对订单/退款/营业数据；测试空值、错误店铺及过期规则。
- 浏览器登录返回、刷新历史、多标签退出、快切账号及网络中断；验证无私人结果串账号。
- 新身份与旧对话历史的兼容决策、监控保留/清理策略、请求限流、超时取消进一步核对。
- 真实模型工具选择、分页、售后语音与多店切换评测；旧DIY/贺卡/语音回归。

## 已知边界

新版身份与旧 external_user_id 身份不同，旧历史不会自动迁移。当前售后仅基于订单退款字段，不是多工单系统。没有人工转接、DIY门店确认下单、独立知识库导入服务。监控统计为工具查询成功率，不是办理完成率；无订单号/正文/票据日志。

## 更新文件与回滚

更新清单以两仓库最终 git diff 为准，包含 customer* 模块、工具/路由/卡片、配置和监控。提交与构建 SHA256 在正式打包时填写，不预填发布结果。先部署兼容后端，再部署H5，开关保持关闭后做灰度；回滚先关开关再还原应用，新增监控表保留，不盲目整库还原。
