## 1. 双库边界

```
① 内部 PostgreSQL（自有，可读写）
   DATABASE_URL=postgresql://...@postgres:5432/flora_agent
   init_db() 启动时执行 backend/storage/db.py 的 _SCHEMA（全 IF NOT EXISTS）
   内容：会话/消息/记忆/DIY方案/生图任务/字段映射/监控埋点
   ⚠ 不含任何平台商品、店铺、订单（镜像方案已废弃删除）
② 平台外部 MySQL（只读，不归本项目所有）
   连接串：环境变量 PLATFORM_DB_<SOURCE_ID>_URL
   例：PLATFORM_DB_MAIN_URL=mysql://ai_readonly:***@host:3306/flower_shop
   方言：mysql:// 与 mysql+pymysql://（也支持 postgresql://）
   约束：连接后立即 SET SESSION TRANSACTION READ ONLY
   内容：平台真实商品/店铺/订单，经「字段映射」按标准实体暴露
```

- 生产禁止 SQLite：`config.py:28-37` 校验 `DATABASE_URL` 必须为 `postgresql://`；`db.py:77-83` 二次拦截。
- **连接串永不进入 LLM 上下文**：`external.py:43` 只从 `os.getenv` 读取；`discover` 只返回表名/列名/类型与**脱敏样本**（`_redact()`，`external.py:95-101`：命中 `password/token/secret/phone/mobile/email/address/pay` 的列只回 SHA256 前 10 位）。

| `user_preferences` | 长期偏好（进 system prompt） | `memory_tools.py` |

| `notifications` | 站内信（写入为空实现，保留） | `storage/notify.py`（no-op） |
| `image_tasks` | 生图异步任务 | `storage/tasks.py` |

| `call_logs` | 调用监控埋点（每次对话一行） | `observability.py` |
| `tool_call_logs` | 工具级埋点 | 同上 |

### 2.1 `sessions`

- `session_id` TEXT PK：`uuid4().hex`，回传宿主做多轮
- `user_id` TEXT NOT NULL：派生 user_id（如 `wxmini_<sha256前24>`）
- `stage` TEXT NOT NULL DEFAULT `'analyze'`：`SessionStage` 值，仅 UI 焦点
- `title` TEXT：首条消息前 20 字
- `preview` TEXT：最近消息摘要；**同时复用为 `FlowerRequirement` 的 JSON 存放位**（`memory.py:85-102`）
- `shop_id` TEXT：**店铺锁定**，建会话写入，会话内不变
- `created_at`/`updated_at` TIMESTAMPTZ NOT NULL：列表按 `updated_at DESC`

### 2.2 `messages`

- `id` BIGSERIAL PK：回放顺序依赖它（`ORDER BY id ASC`）
- `session_id` TEXT NOT NULL：无外键，删会话时手工级联（`memory.py:220-221`）
- `role` TEXT NOT NULL：`user`/`assistant`/`tool`；**`tool` 只入库不回放**（`memory.py:168` 跳过），避免污染 LLM 上下文
- `content` TEXT：正文
- `ui` TEXT：**JSON 字符串**（如 `"text"`、`"plan_card"`），读取时 `json.loads`，前端亦需 parse
- `data` TEXT：卡片数据 JSON 字符串
- `created_at` TIMESTAMPTZ NOT NULL

### 2.3 `memories`

- `id` BIGSERIAL PK
- `user_id` TEXT NOT NULL
- `category` TEXT NOT NULL：`<session_id>`（会话级 JSON）或 `flag:<session_id>`（标志位）
- `key` TEXT NOT NULL：`latest_diy_plan`/`selected_plan`/`image_confirmed`/`plan_pushed`
- `value` TEXT NOT NULL：通常 JSON 字符串
- `confidence` DOUBLE PRECISION DEFAULT 1.0：预留
- `created_at`/`updated_at` TIMESTAMPTZ
- 唯一索引 `idx_memories_unique(user_id, category, key)` + `ON CONFLICT DO UPDATE` 实现幂等（`memory.py:235-241`）

### 2.4 `diy_plans`（项目自产资产）

- `id` TEXT PK：`DIY_<uuid前6>` 或传入 `plan_id`；`user_id` TEXT NOT NULL：归属
- `fingerprint` TEXT NOT NULL：去重键，`(user_id, fingerprint)` 命中即判重复不入库（`diy.py:84-86`）
- `name` TEXT NOT NULL；`requirement` TEXT：用户原始需求
- `recipient`/`occasion`/`style` TEXT：送谁 / 场合 / 风格；`budget` DOUBLE PRECISION：预算（元）
- `color_scheme` TEXT：JSON 数组；`flowers` TEXT：JSON `[{bucket: 主花/填充/叶材, name, ratio}]`
- `packaging`/`meaning` TEXT：包装 / 寓意；`diy_steps` TEXT：JSON 数组（分步插花指引）
- `care_tips`：养护建议；`card_message`/`card_image_url`：贺卡寄语 / 贺卡图
- `budget_breakdown` TEXT：JSON 对象；`effect_image_url` TEXT：生图完成后回填（`agent.py:356-363`）
- `difficulty`/`est_time`/`shelf_life`/`suitable_for`/`caution`/`mood_tags`：难度、耗时、保鲜期、适用场景、注意、情绪标签
- `status` DEFAULT `'confirmed'`；`order_count` INTEGER DEFAULT 0（热度，排序用）；`source_user_id` TEXT（预留）
- `created_at`/`confirmed_at` TIMESTAMPTZ NOT NULL

### 2.5 `image_tasks`

- `task_id` TEXT PK：`uuid4().hex[:16]`
- `user_id` TEXT：归属（轮询时严格过滤）；由 `ALTER TABLE … ADD COLUMN IF NOT EXISTS` 补齐（`db.py:32`）
- `status` TEXT NOT NULL：`processing`/`done`/`failed`；`error` TEXT：失败原因
- `prompt` TEXT NOT NULL：取方案 `effect_prompt`；`result_url` TEXT：`/generated/{task_id}.png` 或拼 `IMAGE_PUBLIC_BASE_URL` 的绝对地址
- `created_at`/`updated_at` TIMESTAMPTZ DEFAULT NOW()：每次状态变更刷新 `updated_at`

### 2.6 `mapping_drafts`

- `id` TEXT PK（uuid4）；`source_id` TEXT NOT NULL：对应 `PLATFORM_DB_<SOURCE_ID>_URL` 的大写形态
- `schema_name` TEXT NOT NULL：MySQL 下实际是**数据库名**（`flower_shop`），见 `external.py:269-275`
- `schema_fingerprint` TEXT NOT NULL：schema profile 的 sha256；结构变则指纹变，形成新版本序列
- `version` INTEGER DEFAULT 1（同 `(source_id, fingerprint)` 内自增）；`status` TEXT DEFAULT `'draft'`：`draft`→`reviewed`→`approved`→`active`，或 `revoked`
- `draft_json` JSONB NOT NULL：映射正文（见 §4）；`created_by`/`created_at`、`reviewed_by`/`reviewed_at`
- 索引 `idx_mapping_drafts_source(source_id, schema_fingerprint, version DESC)`

### 2.7 `call_logs` / `tool_call_logs`（监控埋点）

`call_logs`：`id BIGSERIAL PK`、`user_id TEXT NOT NULL`、`platform_id TEXT`（JWT 的 `platform`，仅归因不鉴权）、`session_id TEXT`、`model TEXT`、`prompt_tokens`/`completion_tokens INTEGER DEFAULT 0`（预留，`observability.record_llm` 当前无副作用）、`tool_calls INTEGER`、`latency_ms INTEGER`、`status TEXT DEFAULT 'pending'`（→`success`/`error`）、`error TEXT`、`created_at TIMESTAMPTZ DEFAULT NOW()`。面板 SSE 用 `id > last_id` 增量拉取。

`tool_call_logs`：`id BIGSERIAL PK`、`call_log_id BIGINT NOT NULL REFERENCES call_logs(id) ON DELETE CASCADE`（**全库唯一物理外键**）、`tool_name`/`status TEXT NOT NULL`、`latency_ms INTEGER DEFAULT 0`（当前恒 0，`chat.py:95` 未测单次耗时）、`error TEXT`、`created_at`。

### 2.8 其余表

- `user_preferences(user_id, key, value, updated_at)`，复合主键 `(user_id, key)`，值存 JSON；读时 `json.loads` 失败按原文返回，内容注入 system prompt 的「用户偏好记忆」段（`agent.py:535-537`）。
- `operations_config(key PK, value)`，键常量见 `storage/config.py:11-18`（`delivery_options`/`shipping_fee`/`coupon_rules`/`faqs`/`announcements`/`recommend_weights`/`service`），当前非主用。
- `notifications(id PK, user_id, type, title, body, ref_type, ref_id, push_channel DEFAULT 'inbox', is_read INTEGER DEFAULT 0, created_at)`，写入为空实现。

### 2.9 索引

`idx_memories_unique(memories: user_id, category, key)` UNIQUE、`idx_sessions_user(sessions: user_id, updated_at DESC)`、`idx_messages_session(messages: session_id, id ASC)`、`idx_memories_user(memories: user_id, category)`、`idx_image_tasks_updated(image_tasks: updated_at DESC)`、`idx_image_tasks_user(image_tasks: user_id, updated_at DESC)`、`idx_mapping_drafts_source`、`idx_call_logs_created(call_logs: created_at DESC)`、`idx_call_logs_platform(call_logs: platform_id, created_at DESC)`、`idx_tool_call_logs_call(tool_call_logs: call_log_id)`。

### 2.10 SQL 占位符约定（易错）

**仓储代码统一写 `?`，由适配器转成 psycopg 的 `%s`**（`db.py:86`：`re.sub(r'(?<!%)\?', '%s', sql)`）。

- 转换在 `ConnectionAdapter.execute/executemany`（`db.py:98-106`），上层无需关心 psycopg；负向后顾 `(?<!%)` 避免破坏已写好的 `%s`，但**同一条 SQL 不要混用两种占位符**。
- 例外：`backend/data_gateway/external.py` 直连外部库，**原生用 `%s`**，不走适配器。
- 连接按线程复用（`threading.local()`，`db.py:20`、`:115`）：不要在线程间传递连接，也不要在 `run()` 线程外持有 cursor。

## 3. 平台只读库（MySQL `flower_shop`）

```python
# backend/data_gateway/external.py:252（节选）
if dialect == 'postgresql':
    conn.execute('SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY')
if dialect == 'mysql':
    cur.execute('SET SESSION TRANSACTION READ ONLY')
```

MySQL 兼容坑：① 无 `public` schema 概念，`_resolve_schema()` 回退为 `DATABASE()`；② 标识符用反引号（PG 用双引号），`database`/`user` 是保留字必须反引号（`external.py:62-79`）；③ 大小写不敏感用 `LIKE` 而非 `ILIKE`（`external.py:82-84`）；④ SSL 仅要求加密时用 `ssl_mode='REQUIRED'`，以**签名探测**判断 pymysql 是否支持（镜像源曾混入自报 2.x 的旧分支，`external.py:206-218`）。

### 3.2 `products` 表（映射为 `plan` 实体）

| canonical | 实际列 | 说明 |
|---|---|---|
| `id` | `id` | 商品主键 → 输出 `plan_id` |
| `name` | `name` | 商品名 |
| `price` | `price` | **原始单位「分」**（如 `8800`） |
| `stock` | `stock` | 库存 |
| `image` | `image` | **相对路径**（如 `/uploads/products/...`） |
| `shop_id` | `owner_shop_id` | 店铺外键（无需 JOIN `shop_products`） |

展示层转换由映射 `transforms` 完成（`external.py:111-157`）：`{"price": "cents_to_yuan", "image": "prepend_url:https://aistore.xiangbinmeigui.com"}`。

- `cents_to_yuan`：`8800 → 88.0`；`prepend_url:<BASE>`：已是 `http(s)://` 则原样，否则拼前缀。
- ⚠️ 支持 `only` 白名单（`external.py:142-150`）：**下单回读时只对 `image` 做前缀转换，`price` 必须保留原始「分」**，否则平台订单金额错乱。

## 4. 实体字段映射机制

平台库表结构各异，智能体只认标准实体 `plan/shop/order/user`，映射层负责翻译。

### 4.1 草案结构（`mapping_drafts.draft_json`）

```jsonc
{
  "status": "active", "source_id": "s001", "dialect": "mysql",
  "schema_fingerprint": "manual:s001:flower_shop",
  "entities": {
    "plan": { "selected": {
        "table": "products",
        "columns": { "id":"id", "name":"name", "price":"price", "stock":"stock",
                     "image":"image", "shop_id":"owner_shop_id" },
        "transforms": { "price":"cents_to_yuan", "image":"prepend_url:https://..." },
        "confidence": 1.0, "evidence": [...], "risks": [...] }, "alternatives": [] },
    "shop": { "selected": { "table": "shops", "columns": {...} } }
  },
  "requires_human_review": [...]
}
```

候选列按表名/字段名启发式打分生成（`mapper.py:24-70` 的 `CANONICAL_ENTITIES` 定义各实体候选表名与列名；评分见 `_score_table`/`_pick_column`）。置信度 < 0.85 写入 `requires_human_review`。

### 4.2 状态机

```
draft ──► reviewed ──► approved ──► active
  │                                   │
  └──────────► revoked ◄──────────────┘（同 source 旧版本自动 revoked）
```

白名单 `{'reviewed','approved','active','revoked'}`（`mapping_store.py:29`）；**置 `active` 时同 `source_id` 其它 active 版本自动 `revoked`**（`:38-39`），同一数据源永远只有一个生效版本；每次变更写 `mapping_audit`（记录 `previous_status`、`version`）。
**查询只看 active**：`get_active_mapping()`（`:52`）按 `version DESC LIMIT 1`；无 active 时 `query_external_entity` 抛 `PermissionError('no active mapping for source')`（`external.py:328`），**不回退草案**。

### 4.3 查询时如何使用

```python
# backend/data_gateway/external.py:316（节选）
active = get_active_mapping(source_id)
selected = active['draft_json']['entities'][entity]['selected']
aliases = [f'{quote(actual)} AS {quote(canonical)}' for canonical, actual in columns.items()]
sql = f'SELECT {",".join(aliases)} FROM {schema}.{table}'
if keyword and columns.get('name'): sql += ' WHERE name LIKE %s'
if shop_id and columns.get('shop_id'): sql += ' AND shop_id = %s'   # 店铺锁定
sql += ' LIMIT %s'      # 硬上限 100
```

安全约束：**标识符（schema/table/column）全过 `_IDENTIFIER = ^[A-Za-z_][A-Za-z0-9_]*$`**，非法即 `PermissionError`（`external.py:323-339`）；**不接受调用方传入任意 SQL**。

### 4.4 相关工具

`platform_db_discover` → `platform_mapping_draft` → `platform_mapping_save_draft` → `platform_mapping_set_status(status='active')` → `platform_db_query_entity`；另有 `platform_mapping_list_drafts`、`platform_mapping_get_active`、`platform_db_test_connection`、`platform_db_sample_table`（样本最多 5 行且脱敏）。

## 5. `image_tasks` 与 `migrations/001_image_tasks.sql`

有 DDL 权限时 `init_db()` 自动建表；**数据库由 DBA 托管、应用账号无建表权限时，需人工执行** `migrations/001_image_tasks.sql`，否则启动自检 `check_task_storage()` 失败并拒绝启动（`main.py:50-55`）。

```sql
CREATE TABLE IF NOT EXISTS image_tasks (
    task_id TEXT PRIMARY KEY, user_id TEXT, status TEXT NOT NULL,
    prompt TEXT NOT NULL, result_url TEXT, error TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW());
CREATE INDEX IF NOT EXISTS idx_image_tasks_updated ON image_tasks(updated_at DESC);
ALTER TABLE image_tasks ADD COLUMN IF NOT EXISTS user_id TEXT;   -- 存量表补列
CREATE INDEX IF NOT EXISTS idx_image_tasks_user ON image_tasks(user_id, updated_at DESC);
```状态流转：`create_image_task()` 写入 `processing` 并**立即返回 task_id** → 后台 `_generate_image_async()` 生图（SSRF 校验 → 体积校验 → `save_generated()`）→ `done`/`failed` → 前端 `GET /tasks/{task_id}` 轮询；服务重启时 `recover_incomplete_tasks()` 把残留 `processing` 置 `failed`（"服务重启，请重新生成"）。

## 6. ER 关系

```
                 ┌──────────┐
                 │ sessions │  shop_id（店铺锁定值，非外键）
                 └────┬─────┘
     1:N              │            1:N
┌────────────┐        │        ┌──────────────────┐
│  messages  │◄───────┴───────►│     memories     │ category=<sid> / flag:<sid>
└────────────┘   session_id     └──────────────────┘

user_id 维度四表：user_preferences / diy_plans / notifications / image_tasks（逻辑关联）

┌──────────┐ 1:N ┌──────────────┐  ┌────────────────┐ 1:N ┌───────────────┐
│ call_logs│────►│tool_call_logs│  │ mapping_drafts │────►│ mapping_audit │
└──────────┘CASC └──────────────┘  └───────┬────────┘     └───────────────┘
    唯一物理外键（ON DELETE CASCADE）       │ draft_json「平台库表/列 → 标准实体」
                                           ▼
                              平台 MySQL（只读，跨库无外键）
                                  shops ──1:N── products(owner_shop_id)
```

除 `tool_call_logs.call_log_id` 外**全部为逻辑关联（无物理外键）**——有意为之：会话删除走 `memory.py:214-222` 的显式事务，避免跨表级联不可控。平台侧 `shops → products` 是平台库内部关系，本项目只读、不依赖、不约束。
