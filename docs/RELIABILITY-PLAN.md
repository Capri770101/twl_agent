## 修订规则

1. 用户、会话中保存的方案为权威数据；模型不得重建历史版本作为修改起点。
2. 仅修改用户授权字段；区分「改预算」和「保留预算」。无法可靠判定时澄清，不扩大授权。
3. 配色修改保留花材、数量和参考报价；包装材料变更可能影响费用，不能无条件承诺原价。
4. 模型错误、越界输出和超时不覆盖原方案，不保存失败结果，也不据失败结果提交图片任务。
5. 所有描述、复制清单、生图提示词从最终有效结构生成。
6. 新版本关联实际父版本。历史版本选择和并发修订需要显式规则，不可静默覆盖最新版本。

### 历史版本与预览复用（本地实现）

当前会话增加 diy_plan_versions 完整快照；恢复已存在版本只切换当前方案，不删除后续版本。恢复第一版后再改，创建下一序号版本且 parent_id 指向第一版。revise_diy_plan 支持规范指令“用回第N版”，提示词要求模型对恢复请求使用该工具。历史缺失明确报错，旧会话无法找回未保存过的早期快照。

图片任务按用户/会话及视觉指纹查找，指纹包含花材支数、配色、包装、风格和店铺。processing/done 复用；failed 创建新任务。不因名称和报价标签变化重复生图。历史恢复与失败重试专项已加入，全量 pytest 通过。尚未实现前端版本列表按钮，也尚未验证并发首次生图去重和多进程版本写入原子性；该功能未部署，需继续完成这些边界后验收。

### 2026-09-28 真实模型隔离复验

使用生产镜像与提供方配置启动一次性容器，将未发布 agent 代码只读挂载；调用修订函数，未替换线上服务、未提交图片任务或订单。起点为规则引擎生成的 200 元方案，不是完整 HTTP 会话测试。

首轮发现包装颜色补丁缺少 changes 外层、降预算时模型擅自换包装。修正为：扁平补丁仍必须严格满足字段白名单；普通修订中未授权的包装/配色/风格取原稿再重算。

修正后四步均成功：配色→版本2，包装粉色→版本3，等总支数换洋桔梗→版本4，预算降到100并允许减量→版本5、估价96元。前两步用料和报价均不变，后两步保留包装与配色。16项专项与全量 pytest 均通过。单组真实调用仅证明该组场景通过，不代表任意自然语言覆盖；本批代码仍未发布，HTTP端到端/页面验收待做。

专项自动化现为 16 项并通过（`python -m pytest tests/test_revision_patch.py -q`）。增加了换花但总支数不变、总数漂移拒绝、预算降低且保留花材、超预算拒绝、每种花数量锁定。总支数与逐花材支数分开检查；明确锁定总数不再误拦等量换花。另以真实规则引擎产出的完整方案验证两次视觉修改后花材、fees、预算明细不变。最终候选约束测试隔离了模型和定价，用于检查拒绝逻辑，不代表真实模型稳定完成复杂修改；真实模型复验仍待进行。

- 连续修改三轮：第一版粉白、第二版香槟白、第三版粉色包装；检查花材/支数/预算、版本和图片任务。
- 换花但保留预算、降低预算但保留支数：检查冲突处理和说明。
- 模型返回越界字段、超时、空结果：原方案和会话最新版本不改变。

- 保存时图片未完成，稍后重新进入：检查图片能否补齐。
