## 1. 数据如何到达前端

本服务是**纯后端 API**，只产出结构化数据；**所有 UI 渲染、按钮交互、页面跳转都由宿主前端负责**。

```
宿主后端: POST /auth/token (X-API-Key) → JWT + user_id
小程序  : POST /chat 或 /chat/stream (Authorization: Bearer <JWT>)
后端    : ChatResponse { reply, ui, data, action, session_id, stage, products }
小程序  : 按 ui 选组件 → data 交给组件 → 保存 session_id
```

| 字段 | 必渲染 | 说明 |
|---|---|---|
| `reply` | ✅ | 中文说明。**组件缺失时也要展示它** |
| `ui` | — | 组件选择器：`text`/`dialog_options`/`plan_card`/`shop_card`/`order_card`/`pay_jump`/`image_task`/`greeting_card` |
| `data` | — | 与 `ui` 一一对应；**只消费已知字段，多余字段忽略并透传** |
| `action.type` / `required_capabilities` / `fallback` | — | 平台中立的下一步动作 / 宿主应具备的能力（**出现过而你没实现 = 前端缺口**）/ 能力缺失时的降级文案 |
| `session_id` | ✅ | **必须保存**，下一轮回传，否则每轮都是新会话 |
| `stage` | — | 会话进度，可展示流程走到哪一步 |

> 卡片按钮动作统一以**用户消息**形式发回 `/chat`（点「换一款」就发一句「换一款」），不另设回调接口。

## 2. UI 卡片契约（8 种）

各卡片的 `action.type`（括号内为 `required_capabilities`）：`text`=show_text（无）· `dialog_options`=show_options(`show_options`) · `plan_card`=show_plan(`show_plan_page`) · `shop_card`=show_shop(`show_shop_page`) · `order_card`=create_order(`create_order`) · `pay_jump`=open_payment(`open_payment`) · `image_task`=start_image_task(`start_image_task`) · `greeting_card`=show_greeting_card(`show_greeting_card`)。`required_capabilities` 是**宿主需具备的能力**，不是智能体可调接口。

### 2.1 `text` — 文本气泡（兜底，**最低要求**）

知识问答、需求澄清、降级兜底时出现；**渲染 `reply` 即可**，`data` 通常为空；无附加能力。

```json
{"reply": "红玫瑰花语是热情与爱情，适合表白、情人节使用。", "ui": "text", "data": {}}
```

### 2.2 `dialog_options` — 选项按钮

需要用户多选一时出现；**渲染 `reply` + 按钮，点选把 `value` 发回 `/chat`**；能力 `show_options`。

```json
{"reply": "你想要哪种方案？", "ui": "dialog_options",
 "data": {"options": [{"label": "现货花束（约200元）", "value": "existing"}, {"label": "DIY 定制（按你喜好）", "value": "diy"}]}}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `options[].label` | string | 展示文案 |
| `options[].value` | string | 点选后发回对话的值 |

### 2.3 `plan_card` — 方案卡片（**DIY 与现成共用**）

推荐现成方案、DIY 方案设计/改版完成时出现；**渲染名称/价格/描述/效果图 + 「确认」「修改 / 换一款」「生成效果图」**；能力 `show_plan_page`。⚠️ **DIY 与现成共用本组件，不要为 DIY 另做一套**。

```json
{"reply": "为你推荐 3 个生日花束方案：", "ui": "plan_card",
 "data": {"plans": [{"plan_id": "P001", "name": "生日玫瑰花束", "price": 199.0,
   "desc": "红玫瑰 11 支 + 满天星，热烈浪漫，适合生日祝福。", "effect_image_url": "",
   "merchant_name": "向阳花艺", "tags": ["生日"], "style": "现代"}]}}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `plan_id` | string | ✅ | 用户「确认」时回传 |
| `name` | string | ✅ | 方案名称 |
| `price` | number | ✅ | 价格（**元**） |
| `desc` | string | ❌ | 描述；`tags` / `style` 为运行时附加，可展示可忽略 |
| `effect_image_url` | string | ❌ | 效果图，**可能为空**，相对路径需拼域名 |
| `merchant_name` | string | ❌ | 商家名，**可能为空** |

### 2.4 `shop_card` — 店铺卡片

推荐可配送、库存匹配的店铺时出现（传了 `location` 按距离排序）；**渲染名称/距离/价格区间/评分 + 「选这家」**；能力 `show_shop_page`。

```json
{"reply": "以下 3 家店可配送且备货充足：", "ui": "shop_card",
 "data": {"shops": [{"shop_id": "S001", "name": "向阳花艺（五道口店）", "distance_km": 1.2,
   "price_range": "中高端", "rating": 4.8, "delivery": "1小时内送达"}]}}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `shop_id` | string | 店铺 ID（下单回传） |
| `name` | string | 店铺名称 |
| `distance_km` | number | 距离（公里） |
| `price_range` | string | 价格区间（可为空） |
| `rating` | number | 评分 0~5（可为空） |

### 2.5 `order_card` — 订单确认卡

用户确认方案+店铺后创建订单时出现；**渲染订单 ID、明细（名称/单价/数量/小计）、合计、优惠、方案类型 + 「确认支付」「重新选择」**；能力 `create_order`。⚠️ 订单写入/幂等/金额一致性**由后端保证**，前端只展示与确认。

```json
{"reply": "订单已为你创建，请确认：", "ui": "order_card",
 "data": {"order_id": "ORD_20260902_0001", "items": [{"name": "红玫瑰", "qty": 11, "unit_price": 12.0, "price": 132.0}],
   "total_price": 199.0, "discount": 0, "plan_type": "existing", "effect_image_url": "/generated/55f7e131465f4563.png"}}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `order_id` | string | 订单 ID |
| `items[]` | array | `name`/`qty`/`unit_price`/`price`（`/image`） |
| `total_price` | number | 合计（元） |
| `discount` / `plan_type` | number / string | 优惠金额；方案类型 `existing`（现成）/ `diy`（定制） |

### 2.6 `pay_jump` — 支付跳转

订单已创建需付款时出现；**渲染「去支付」入口，点击打开宿主平台自己的收银台**（智能体不接触支付密钥）；能力 `open_payment`。

```json
{"reply": "订单已生成，请点击去支付完成付款：", "ui": "pay_jump",
 "data": {"order_id": "ORD_20260902_0001", "page_path": "/pages/order/confirm",
   "params": {"order_id": "ORD_20260902_0001", "total_price": 199.0, "shop_id": "S001"}, "total_price": 199.0}}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `order_id` | string | 订单 ID |
| `page_path` | string | 小程序页面路径，默认 `/pages/order/confirm` |
| `params` | object | 跳转参数 |

> 小程序可直接 `wx.navigateTo({ url: page_path + '?' + queryString(params) })`。

### 2.7 `image_task` — 生图任务（**需轮询**）

用户要求生成效果图 / DIY 方案定稿后自动触发；能力 `start_image_task`。⚠️ **异步任务**（`qwen-image-3.0`，实测 **约 54 秒**），**不能把 `task_id` 当图片 URL**。

```json
{"reply": "正在为你生成效果图，大约需要 1 分钟：", "ui": "image_task",
 "data": {"task_id": "55f7e131465f4563", "poll": "/tasks/55f7e131465f4563", "result_url": ""}}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `task_id` | string | 任务 ID |
| `poll` | string | 轮询路径，即 `GET /tasks/{task_id}` |
| `result_url` | string | **已完成时**直接给图片 URL；为空表示仍在生成 |

**前端流程**：① 展示「生成中…」→ ② 每 **2 秒**轮询 `GET https://api.tiaowulan.com/tasks/{task_id}`（**必须带 JWT**）→ ③ `done` 取 `result_url` 展示；`failed` / `not_found` **立即停止**。

```js
const timer = setInterval(async () => {              // 另建议加 90s 硬超时后 clearInterval 并提示重试
  const r = await request({ url: `${BASE}/tasks/${taskId}`, header: authHeader() })
  if (r.status === 'done') { clearInterval(timer); onDone(prefix(r.result_url)) }
  if (r.status === 'failed' || r.status === 'not_found') { clearInterval(timer); onFail(r.error) }
}, 2000)
```

> 状态由服务端持久化；服务重启会把遗留 `processing` 批量置 `failed`，**不要无限轮询**。

### 2.8 `greeting_card` — 电子贺卡（**同步出图，无需轮询**）

下单后智能体主动询问，或用户直接要求做贺卡时出现；**渲染 `data.image_url` 大图 + 文案 + 「换模板 / 改文案重做」**；能力 `show_greeting_card`。⚠️ 贺卡是**模板合成、同步完成**的，**不要对它轮询**。

```json
{"reply": "贺卡做好啦，送给妈妈的生日祝福～", "ui": "greeting_card",
 "data": {"image_url": "/generated/greet_20260904120000_ab12cd.png", "text": "妈妈，生日快乐！愿岁月对您温柔……",
   "recipient": "亲爱的妈妈", "sender": "爱你的女儿", "template": "warm",
   "note": "模板 warm（温暖奶油风，适合家人/温馨场合）"}}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `image_url` | string | 贺卡大图（**相对路径，需拼域名**） |
| `text` | string | 祝福语正文（超长已截断） |
| `recipient` / `sender` | string | 收卡人称呼 / 落款（可为空） |
| `template` | string | `warm` / `blush` / `green` / `letter` / `night` |
| `note` | string | 备注（含模板风格说明，可展示为小字） |

> 「换模板 / 改文案重做」= 把用户原话（「换成墨绿风」「再文艺一点」）作为新消息发回 `/chat`，智能体会再次合成。

## 3. 微信小程序流式实现要点（`/chat/stream`）

小程序**没有 `EventSource`**，必须用 `wx.request` 的分块传输。当前线上 `/chat/stream` 调用为 **0**，宿主仍在用非流式 `/chat`（约 15 s 转圈后整段弹出）——这是体验优化的主要待办。

### 3.1 事件回顾

| 事件 | 载荷 | 前端动作 |
|---|---|---|
| `tool_call` | `{"name":"platform_db_query_entity","status":"ok"}` | 显示「正在查询…」 |
| `text` | `{"content":"…"}` | **追加**到当前气泡 |
| `card` | `{"ui":"plan_card","data":{...}}` | 按 `ui` 渲染，不再解析 text |
| `done` | `{"session_id":"..."}` | 保存 `session_id` |
| `error` | `{"message":"..."}` | 提示错误 + 重试入口 |

### 3.2 参考实现

```js
const BASE = 'https://api.tiaowulan.com'
// 坑①：onChunkReceived 给的是 ArrayBuffer，必须自己 UTF-8 解码
function decodeUTF8(buf) {
  if (typeof TextDecoder !== 'undefined') return new TextDecoder('utf-8').decode(new Uint8Array(buf))
  const bytes = new Uint8Array(buf); let out = ''               // 低版本基础库降级：手写解码
  for (let i = 0; i < bytes.length;) {
    const b = bytes[i++]
    if (b < 0x80)      out += String.fromCharCode(b)
    else if (b < 0xE0) out += String.fromCharCode(((b & 0x1F) << 6) | (bytes[i++] & 0x3F))
    else               out += String.fromCharCode(((b & 0x0F) << 12) | ((bytes[i++] & 0x3F) << 6) | (bytes[i++] & 0x3F))
  }
  return out
}
// 坑②：中文会被切在两个 chunk 中间 → 先缓冲，再按 "\n\n" 切完整事件
export function streamChat({ token, userId, message, sessionId, onEvent, onFinish }) {
  let buf = ''
  const reqTask = wx.request({
    url: `${BASE}/chat/stream`, method: 'POST',
    enableChunked: true,                 // ← 关键：开启分块接收
    timeout: 120000,                     // ← /chat 典型 15s，务必放大（默认仅 60s）
    header: { 'Authorization': `Bearer ${token}`, 'Content-Type': 'application/json' },
    data: { user_id: userId, message, session_id: sessionId },
    success: () => onFinish && onFinish(),   // 坑③：流结束才触发，别在这重复渲染
    fail: (err) => {   // 坑④：不支持分块 → 降级回 /chat 一次性返回，同样按 ui 渲染并保存 session_id
      console.warn('[sse] 分块失败，降级非流式', err)
      wx.request({ url: `${BASE}/chat`, method: 'POST', timeout: 120000, data: { user_id: userId, message, session_id: sessionId },
        header: { 'Authorization': `Bearer ${token}`, 'Content-Type': 'application/json' } }).then(r => onFinish(r.data))
    },
  })
  reqTask.onChunkReceived((res) => {
    buf += decodeUTF8(res.data)
    let idx; while ((idx = buf.indexOf('\n\n')) !== -1) {         // 按空行切出完整事件
      const raw = buf.slice(0, idx); buf = buf.slice(idx + 2)
      let event = 'text', data = ''
      for (const line of raw.split('\n')) {
        if (line.startsWith('event:')) event = line.slice(6).trim()
        if (line.startsWith('data:'))  data += line.slice(5).trim()
      }
      if (data) { try { onEvent(event, JSON.parse(data)) } catch (e) { /* 半包忽略，等下一段 */ } }
    }
  })
  return reqTask
}
```

### 3.3 四个必看坑位

| # | 坑 | 后果 | 处置 |
|---|---|---|---|
| ① | `onChunkReceived` 返回 **ArrayBuffer** | 当字符串用得到乱码 | 手动 UTF-8 解码，低版本基础库用上面的降级解码器 |
| ② | **中文被切在两个 chunk 中间** | 拿到一块就 `JSON.parse` 必崩 | 缓冲到全局 `buf`，按 `\n\n` 切出完整事件；解析失败丢弃等下一段 |
| ③ | `success` 在**流结束时**才触发 | 与 `onChunkReceived` 重复渲染，文本翻倍 | `success` 只做收尾（存 `session_id`、关 loading），不渲染正文 |
| ④ | 老基础库/部分真机不支持 `enableChunked` | 白屏、一直转圈 | `fail` 里降级回 `POST /chat`，保证功能不挂 |

## 4. 通用规则与高频坑位

### 4.1 ⚠️ 图片是相对路径，必须拼域名

`IMAGE_PUBLIC_BASE_URL` 当前**为空**，后端返回 `/generated/55f7e131465f4563.png`；前端必须拼成 `https://api.tiaowulan.com/generated/55f7e131465f4563.png`（已实测公网 200）：

```js
const BASE = 'https://api.tiaowulan.com'
const prefix = (u) => (!u ? '' : (u.startsWith('http') ? u : BASE + u))
```

- 适用：`plan_card.effect_image_url`、`order_card.effect_image_url`、`image_task.result_url`、`greeting_card.image_url`
- 例外：`products[].image` 来自平台库，通常**已是完整 CDN URL**，仍建议走同一个 `prefix()` 兜底

### 4.2 ⚠️ 历史消息里的 `ui` 字段解析

`GET /conversations/{id}/messages` 的 `ui` 在 DB 中是**双层编码**的 JSON 字符串（列里形如 `"\"plan_card\""`）；经 `load_history()` 反序列化一层后返回**字符串** `plan_card`，但不同环境/存量数据可能保留外层引号。统一用兼容函数：

```js
function parseUi(ui) {                    // 兼容 '"plan_card"' 与 'plan_card'，最多解两层
  let v = ui || 'text'
  for (let i = 0; i < 2 && typeof v === 'string' && v.startsWith('"'); i++) {
    try { v = JSON.parse(v) } catch (e) { break }
  }
  return typeof v === 'string' ? v : 'text'
}
```

> 历史消息里的卡片同样按第 2 节的组件渲染，**不要只渲染纯文本**。

### 4.3 卡片缺失时降级，不要报错

`if (components[msg.ui]) components[msg.ui].render(msg.data)`
`else renderText(msg.reply || msg.action?.fallback || '')`   ← 永远有兜底

`text` 是唯一必须实现的组件；其余 7 种缺失时一律文本降级。

### 4.4 `session_id` 必须回传

多轮记忆**全靠** `session_id`。不传 = 每轮新会话 = 「聊上句忘下句」。① 首次不传，从响应或流式 `done` 事件拿到并持久化；② **之后每轮都带上**；③ 「新对话」→ `POST /conversations` 新建或下一轮不传；④ 响应里的 `session_id` **始终覆盖**本地值（传入的会话不存在/不属于该用户时后端会静默新建）。

### 4.5 用 `GET /ui-contract` 程序化核对

`curl -s https://api.tiaowulan.com/ui-contract | jq '.required_components'`

把返回的 8 项 `required_components` 与已实现组件做差集，非空即为缺口。**接入前与每次后端升级后各跑一次**，避免字段漂移。

## 5. 接入自检清单

- [ ] 域名白名单已加 `https://api.tiaowulan.com`
- [ ] `user_id` 用 `/auth/token` 派生值（非 openid、非自造）→ 不 403
- [ ] 每轮回传 `session_id`，且用响应里的值覆盖本地
- [ ] `text` 已实现，其余 7 种卡片按 `/ui-contract` 实现（差集为空）
- [ ] `plan_card` 名称/价格/描述/效果图 + 确认、修改、生成效果图
- [ ] `image_task` 生成中 + 2 s 轮询 + 结果图 + 失败/超时终止；`greeting_card` 直接展示不轮询
- [ ] 所有图片 URL 走 `prefix()`，无 404；历史消息按 `ui` 渲染卡片而非纯文本；组件缺失按 `reply` 降级
- [ ] 流式：文字逐段追加、`card` 正确渲染、`done` 存 `session_id`、不支持时自动降级
