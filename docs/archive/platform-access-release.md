# 平台数据授权（第二批）

## 配置

JWT 已验证的 platform 字段决定数据授权，不接受请求体或工具参数指定身份。
在各实例环境中配置 JSON 映射，例如：

```dotenv
PLATFORM_SOURCE_ACCESS={"wxmini":["aistore"],"h5app":["aistore"],"wechat":["aistore"]}
```

平台名称必须与接入平台 ID 相同。匿名演示使用 `anonymous`；只在明确需要时授权它。
未列出的平台、缺少 platform 的旧 JWT、错误 JSON 均无法查询平台数据。
老 JWT 应重新通过登录/平台换 token 接口签发。

历史单一公开数据源部署可以显式设置 `PLATFORM_SINGLE_SOURCE_COMPAT=true`：
仅映射为空且恰好配置一个数据源时，允许该源公开查询；有两个数据源时自动拒绝。
多租户部署应使用显式映射，不依赖兼容开关。

## 权限范围

- C 端智能体运行期间，数据源列表、底层 HTTP/DB 查询和价格/花材缓存均按授权范围隔离。
- C 端运行即使开启 ENABLE_OPS_TOOLS 也不会开放运维工具。
- 仅开放 plan/shop；order/user 缺少用户归属映射，底层查询拒绝执行。
- DB 锁店查询缺少过滤字段时拒绝；shop 实体按自身 id 过滤。
- 精确 ID 查询缺少 id 映射时拒绝，不再静默放宽。
- 无请求上下文的内部运维调用仍可访问已配置数据源，不应直接暴露为外部接口。

## 发布与验收

本批无需数据库迁移。发布前分别核对生产、演示的已配置平台 ID 与数据源 ID，
只读取标识，不输出密钥；先写授权映射，再发布对应镜像。
先演示后生产，验证允许的平台可查商品，未知平台/越权数据源/私有实体被拒绝。
检查从商品页面进入的锁店查询、DIY 估价和同店铺 ID 跨平台隔离。
回退时恢复旧镜像，新增配置可保留（旧版忽略）。
