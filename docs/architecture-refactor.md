# Agent 架构演进决策（第一阶段）

## 当前实现

当前使用自研 ReAct + 业务阶段状态机；FastAPI 提供 API/SSE，OpenAI SDK 接模型，工具注册表负责工具协议，PostgreSQL 保存会话与偏好。没有 LangChain 或 LangGraph 运行依赖。agent/agent.py 同时承担上下文、循环、路由干预、工具执行和结果清理。

## 框架决策

第一阶段暂不引入 LangGraph。先抽离业务策略与执行契约，保持 API、工具权限与输出行为可回归。LangGraph 可以在后续替代执行调度，但它不会自动整理业务规则，也不代替数据落地校验。

当出现明确的持久化暂停/恢复、人工审批、多分支工作流需求时，用独立原型验证 LangGraph。验收需要覆盖 checkpoint 的用户隔离、超时取消、工具幂等、重试不重复副作用和 SSE 兼容；不可仅因节点拆分完成就宣布迁移成熟。

## 第一阶段边界

1. 保留归属校验、店铺锁、只读约束、SSRF 与结果证据校验为硬执行代码。
2. 抽取路由策略（工具集合、轮数等）为声明式配置，加载时验证；关键词识别先保持行为不变。
3. 整理 context、executor、formatter、contracts 边界，逐步提取；不得以行数目标删除现有校验。
4. 把现有测试归为路由/权限/事实/卡片/记忆/流式契约。静态评测集校验与模型行为评测分开报告，后者不能用前者的通过代替。

JSON 作为首轮策略格式，避免新增 YAML 依赖；格式不是架构目标，配置校验与稳定行为才是。

## 后续迁移前提

- 慢路径分类需要确认模型、成本和延迟预算；低置信度可以扩大候选域，不能授予权限。
- 事件记忆需覆盖旧数据迁移、事件去重、投影版本、幂等重建、用户删除与留存政策。当前未实施迁移。
- 滚动摘要需来源范围与摘要水位，避免丢失用户改口和把临时预算变成长期偏好。
- 真正增量文本需要先确定可公开的证据边界；禁词前缀检查不能证明订单/价格/投递回执真实。现有模型流并非未接入，而是用户文本被完整校验阶段缓冲。

第一阶段不引入新模型，不改数据库结构，不推送或部署。
