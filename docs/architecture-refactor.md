# Agent 架构演进决策（第一阶段）

## 当前实现

当前使用自研 ReAct + 业务阶段状态机；FastAPI 提供 API/SSE，OpenAI SDK 接模型，工具注册表负责工具协议，PostgreSQL 保存会话与偏好。没有 LangChain 或 LangGraph 运行依赖。agent/agent.py 同时承担上下文、循环、路由干预、工具执行和结果清理。

## 框架决策

第一阶段暂不引入 LangGraph。先抽离业务策略与执行契约，保持 API、工具权限与输出行为可回归。LangGraph 可以在后续替代执行调度，但它不会自动整理业务规则，也不代替数据落地校验。

当出现明确的持久化暂停/恢复、人工审批、多分支工作流需求时，用独立原型验证 LangGraph。验收需要覆盖 checkpoint 的用户隔离、超时取消、工具幂等、重试不重复副作用和 SSE 兼容；不可仅因节点拆分完成就宣布迁移成熟。

## 第一阶段边界

1. 保留归属校验、店铺锁、只读约束、SSRF 与结果证据校验为硬执行代码。
2. 抽取路由策略（工具集合、轮数等）为声明式配置，加载时验证；关键词识别先保持行为不变。配置中的工具集合只是候选收窄，不是授权；注册工具名校验不代表会话有权调用，运行时可见性、用户归属和店铺锁仍在硬执行层。
3. 整理 context、executor、formatter、contracts 边界，逐步提取；不得以行数目标删除现有校验。
4. 把现有测试归为路由/权限/事实/卡片/记忆/流式契约。静态评测集校验与模型行为评测分开报告，后者不能用前者的通过代替。

JSON 作为首轮策略格式，避免新增 YAML 依赖；格式不是架构目标，配置校验与稳定行为才是。

## 后续迁移前提

- 慢路径分类需要确认模型、成本和延迟预算；低置信度可以扩大候选域，不能授予权限。
- 事件记忆需覆盖旧数据迁移、事件去重、投影版本、幂等重建、用户删除与留存政策。当前未实施迁移。
- 滚动摘要需来源范围与摘要水位，避免丢失用户改口和把临时预算变成长期偏好。
- 真正增量文本需要先确定可公开的证据边界；禁词前缀检查不能证明订单/价格/投递回执真实。现有模型流并非未接入，而是用户文本被完整校验阶段缓冲。

第一阶段不引入新模型，不改数据库结构，不推送或部署。

## 第二阶段评估结论

详见 `docs/architecture-phase2-options.md`：当前不立即引入 LangGraph；事件记忆先规划影子投影、幂等与删除；不公开未验证的模型增量。已修正 `arun_stream` 过时的逐字输出说明，`tests/test_public_stream_contract.py` 通过真实流入口锁定最终 `text` 与 `done.reply` 一致及无原始 `text_delta`。这些是设计和本地契约，不代表迁移或线上行为评测已完成。

## 已建立的行为基线

- 上下文：`tests/test_context_budget.py` 验证完整轮次保留和最近超长轮不切断；`tests/test_plan_context.py` 验证 DIY 方案优先、花材/配材/价格摘要及后续方案讨论。
- `trim_history_for_llm` 与 `latest_plan_summary` 已迁到 `agent/orchestration/context.py`；旧入口保留别名，运行调用和原测试继续使用同一实现。两组测试共 18 项通过。
- 路由候选工具和迭代上限迁到 `agent/orchestration/policies/routing.json`，加载器拒绝重复字段、未知工具和不合法值；关键词快路径与客服细分工具域保持一致。`scripts/validate_eval_set.py` 从声明式策略取合法意图并独立做静态校验。
- 新增逐场景路由契约：12 条声明场景必须命中快路径、意图与轮次一致、允许工具不越界且禁用工具不落在候选域。该门禁发现「退款审核」未命中客服快路径、回退全域的缺陷并予以修复。它验证路由策略，不等同真实模型场景评测。
- `scripts/run_eval.py` 的客户票据交换现已在 HTTP 客户端进入上下文后执行；用假客户端测整个执行入口，不向网络请求。真实 HTTP/模型评测尚未执行，因此 12 条声明场景的格式和路由校验仍不能证明业务场景通过。
- 内部术语/数据库字段脱敏、危险标签中和及分隔线清理搬至 `agent/safety/formatter.py`；旧函数名与八步清理流水线依然指向同一实现。三项属于确定性输出约束，不改为 prompt-only；清理顺序由原测试继续锁定。
- `agent/orchestration/executor.py` 已有通过回调注入的 ReAct 模型轮次循环与单轮工具批处理。业务决策、工具权限、证据护栏、存储、卡片对齐以及最终 SSE 发布仍由 `agent/agent.py`/现有工具层执行，执行器本身不导入业务模块；没有以行数门槛代替契约。原先静态扫描 `run()` 字符串的测试改成转录顺序、终结工具不执行及双模型入口的行为测试。
- 梳理记忆迁移前置不变量时修复指定会话 ID 的并发创建竞态：`ON CONFLICT DO NOTHING` 后不能无条件返回该 ID，改为 `RETURNING` 判定插入成功，否则重读并校验拥有者。拒绝并发抢占到的他人会话；这是硬归属约束，不可交给策略配置或模型。
- 此步骤迁移现有上下文选择、安全输出格式化和工具执行/轮次机制，没有实现滚动摘要或事件记忆；不能声称所有业务策略都已配置化。
