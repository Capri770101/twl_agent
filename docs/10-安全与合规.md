## 1. 信任模型（先理解这三条，再看具体机制）

1. **智能体不持有用户身份**：宿主（小程序/H5/App）自有后端负责认证自己的终端用户，再用平台密钥换智能体 JWT。智能体只认 JWT 里的 `sub`。
2. **智能体不持有平台数据主权**：平台库只读，不镜像、不落订单。
3. **密钥分三层，互不复用**：业务 JWT（`JWT_SECRET`）、平台接入（`PLATFORM_API_KEYS`）、监控面板（`DASHBOARD_API_KEY`）必须各自独立，任一泄露不牵连其它。

## 2. 鉴权体系

### 2.1 JWT 签发与校验

```python
# backend/auth.py:26
def create_access_token(user_id, platform=None):
    payload = {'sub': user_id, 'iat': now, 'exp': now + timedelta(hours=settings.JWT_EXPIRE_HOURS)}
    if platform: payload['platform'] = platform      # 仅监控归因，不参与鉴权
    return jwt.encode(payload, _secret(), algorithm='HS256')
```

- 算法固定 HS256，密钥 `JWT_SECRET`（`auth.py:20-23` 未配置直接 `RuntimeError`）。
- 有效期默认 720 小时（30 天，`config.py:93`）。
- 校验：PyJWT `jwt.decode(..., algorithms=['HS256'])`，任何异常统一转 401「登录凭证无效或已过期」（`auth.py:46-47`），不回显 JWT 细节。
- `platform` 字段只用于 `call_logs.platform_id` 归因（`observability.py:38-58`），**不参与任何鉴权判断**。

### 2.2 三种登录端点

| 端点 | 凭证 | 生产可用性 |
|---|---|---|
| `POST /auth/token` | 头 `X-API-Key`（平台密钥）+ 体 `external_user_id` | ✅ 推荐 |
| `POST /auth/wx-login` | 微信 `code` | ✅ 需配 `WECHAT_APPID/SECRET` |
| `POST /auth/anonymous` | 无 | ⛔ 生产默认关闭 |

### 2.3 平台密钥 `PLATFORM_API_KEYS`

- 格式：`platform_id=key`，逗号或换行分隔（`config.py:95-98`），解析见 `auth.py:94-106`。
- 校验用 `secrets.compare_digest`（**常量时间比较**，防时序侧信道，`auth.py:114`）。
- 未配置 → `503`（`auth.py:125-127`）；校验失败 → `401` 并打 warning（`auth.py:129-132`）。
- **信任模型**：持有 Key 的接入方后端负责认证自己的终端用户。因此 Key 一旦下发给不可信方，等于把"签发任意用户身份"的权力交出去。

### 2.4 派生 `user_id` 不一致 → 403

```python
# backend/auth.py:87
def require_user(user_id: str, authenticated_user: str | None) -> None:
    if settings.AUTH_REQUIRED and authenticated_user != user_id:
        raise HTTPException(status_code=403, detail='无权访问其他用户的数据')
```

- 每个业务端点（`POST /chat`、`/chat/stream`、`/chat/reset`、`GET /conversations*`、`POST /conversations`、`GET /tasks/{id}`）都先 `Depends(current_user)` 再 `require_user(req.user_id, ...)`。
- **会话/资源层还有二次校验**：`chat.py:71-74`（会话不属于该用户则视为不存在、重建）、`chat.py:167-169`（历史消息 403）、`memory.py:25`（跨用户访问会话抛 `PermissionError`）、`tasks.py:215-219`（生图任务按 `user_id` 过滤）。
- 派生规则（`auth.py:136-143`）：`sha256(f'{platform_id}:{external_user_id}')[:24]`，前缀为清洗后的 `platform_id`。**原始 openid / 手机号 / 第三方 ID 一律不落库**；微信登录同理（`auth.py:166`）。

### 2.5 生产强制项（`backend/config.py`）

| 校验器 | 位置 | 行为 |
|---|---|---|
| `AUTH_REQUIRED` 强制 | `config.py:45` | `APP_ENV` 为 `prod/production` 时无条件置 `True`，配置里写 `false` 也无效 |
| `JWT_SECRET` 长度 | `config.py:43-44` | 少于 32 位直接抛 `ValueError`，服务起不来 |
| `ANONYMOUS_LOGIN_ENABLED` | `config.py:46-48` | 生产**未在 `.env` 显式声明时强制 `False`**；显式 `true` 会保留（需自行承担风险） |
| CORS 禁通配 | `config.py:51-56` | 生产 `ALLOWED_ORIGINS` 含 `*` → 启动失败 |
| 数据库禁 SQLite | `config.py:28-37` | 生产必须 `postgresql://` |

## 3. 密钥管理边界

### 3.1 绝不能进前端 / 小程序 / git 的项

| 变量 | 泄露后果 | 存放要求 |
|---|---|---|
| `PLATFORM_API_KEYS` | 可签发任意用户身份 | **只在宿主后端与服务端 `.env`**；小程序端只拿换来的 `access_token` |
| `JWT_SECRET` | 可伪造任意用户 JWT | 服务端 `.env`，≥32 位随机 |
| `DASHBOARD_API_KEY` | 监控面板裸奔 | 服务端 `.env`，建议 `openssl rand -hex 32` |
| `LLM_API_KEY` / `IMAGE_API_KEY` | 额度被盗刷 | 服务端 |
| `DATABASE_URL` | 内部库被读写 | 服务端 |
| `PLATFORM_DB_<ID>_URL` | 平台库连接凭据外泄 | 服务端环境变量（**不写进任何配置文件或代码**） |
| `WECHAT_SECRET` | 可冒充小程序换 openid | 服务端 |
| `HY_API_KEY`、`ZHIPU_API_KEY` | 同上 | 服务端 |

### 3.2 已生效的工程约束

- `.gitignore` 已忽略：`.env`、`.env.*`、`data/`、`*.db`、`deploy/certs/`（含私钥 `privkey.pem`）。仓库只提交 `.env.example`（占位值 `REPLACE_WITH_...`）。
- `docker-compose.yml` 通过 `env_file: .env` 注入，不在镜像层固化密钥；`POSTGRES_PASSWORD` 用 `${POSTGRES_PASSWORD:?...}` 强制声明。
- **容器端口收口**：`agent` 只绑 `127.0.0.1:8000`（公网 8000 不可达），`postgres` 不映射宿主机端口，唯一入口是 nginx 443。
- 外部库凭据只经 `os.getenv('PLATFORM_DB_<SOURCE_ID>_URL')` 读取（`external.py:43`），**不进 `settings`、不进日志、不进 LLM 上下文**。

### 3.3 已知待加固项（交接必看）

| 风险 | 位置 | 说明 |
|---|---|---|
| LLM 异常原文进回复 | `agent/agent.py:186-189` | `final_reply = f'抱歉，模型调用出错：{exc}'` —— `exc` 可能含 upstream URL、响应片段。建议改为通用文案 + 服务端记日志 |
| 外部数据源错误信息含环境变量名 | `external.py:46` | 抛 `未配置外部数据源连接：PLATFORM_DB_MAIN_URL`，会经工具结果进入 LLM 上下文。仅泄露变量名不含值，可接受但需知晓 |
| 监控面板密钥在浏览器 `sessionStorage` | `dashboard/app.js` | 关闭标签页即失效；仍需避免共用电脑。建议后续改服务端会话 + 定期轮换 |
| 面板密钥强度 | 线上为 `770101` | 已建议换成 `openssl rand -hex 32`（改 `.env` 后 `docker compose restart agent`） |

## 4. 平台库只读约束（硬边界）

```python
# backend/data_gateway/external.py:252-266（节选）
if dialect == 'postgresql':
    conn.execute('SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY')
if dialect == 'mysql':
    cur.execute('SET SESSION TRANSACTION READ ONLY')
```

四道防线：

1. **会话级只读**：连接建立后立即执行方言对应的只读事务指令（MySQL 与 PG 语句不同，见上）。
2. **账号级只读**：部署要求为智能体账号只授予 `SELECT`（不授予 `INSERT/UPDATE/DDL`）。
3. **不接受任意 SQL**：`query_external_entity` 只按 active 映射拼 `SELECT ... WHERE ... LIMIT`，**没有透传 SQL 的入口**。
4. **标识符白名单**：`_IDENTIFIER = ^[A-Za-z_][A-Za-z0-9_]*$`，schema / table / column 逐一校验，非法即 `PermissionError`（`external.py:323-339`）。

其它约束：

- `limit` 硬上限 100（`external.py:345`）；`sample_rows` 上限 5（`external.py:31`、`:296`）。
- 样本脱敏 `_redact()`（`external.py:95-101`）：列名含 `password / token / secret / phone / mobile / email / address / pay` 时只返回 `sha256(value)[:10]` 占位；其余超 500 字截断。
- 本项目**没有任何向平台库写入的代码路径**（旧的 `db_auto_*` 写单适配器与 `gateway.py` 已删除，见 `mapper.py:11-14`）。

## 5. 生图链路：SSRF 与体积防护

百炼返回的是**带签名、有时效的 OSS 地址**，服务端必须下载转存。下载前先做公网校验：

```python
# backend/storage/tasks.py:17
def _assert_public_image_url(image_url: str) -> None:
    parsed = urlparse(image_url)
    if parsed.scheme not in ('http', 'https'):
        raise PermissionError('invalid image url scheme')
    hostname = parsed.hostname
    if not hostname: raise ValueError('image url missing hostname')
    addresses = socket.getaddrinfo(hostname, None)
    for addr in addresses:
        ip = ipaddress.ip_address(addr[4][0])
        if ip.is_private or ip.is_loopback or ip.is_link_local \
           or ip.is_reserved or ip.is_multicast or ip.is_unspecified:
            raise PermissionError('image url resolves to a private/internal address')
```

- 阻断目标：云元数据服务（`169.254.169.254`）、容器内网、本机回环。
- **遍历所有 DNS 解析结果**（`getaddrinfo` 返回多地址），只要有一个是私网就拒绝——避免"一个公网 IP + 一个内网 IP"绕过。
- 体积上限：`_MAX_IMAGE_BYTES = 20 * 1024 * 1024`（`tasks.py:14`），下载后 `len(content)` 超限即抛错（`:173-175`）。
- 落盘防穿越：`object_store._safe_name()` 只取 `Path(filename).name`（`object_store.py:9-14`），`task_id` 由服务端生成（uuid4 前 16 位）。

残余风险（已知，未修）：

- 校验与下载之间存在 **DNS rebinding / TOCTOU** 窗口（`_assert_public_image_url` 后重新 `dl.get(image_url)`）；需彻底消除应改为校验后锁定 IP 直连。
- 体积检查发生在**完整下载之后**（`img_response.content`），超大响应会先占内存；更稳妥的是先校验 `Content-Length` 再流式读取。

## 7. 数据边界（什么能进 LLM，什么不能）

**允许进入 LLM 上下文**：

- 本轮用户消息 + 最近 `HISTORY_LIMIT`（默认 20）条历史消息；
- `user_preferences` 里的长期偏好；
- 平台库**经映射与脱敏后**的查询结果（商品名/价格/图片/库存等）；
- `platform_db_discover` 的 schema profile（表名/列名/类型 + 最多 5 行脱敏样本）；
- 已接入数据源 ID 列表（由 `_platform_source_ids()` 扫描 `PLATFORM_DB_*_URL` 变量名得出，**只给变量名不含值**）。

**禁止进入 LLM 上下文**：

| 数据 | 阻断方式 |
|---|---|
| `PLATFORM_DB_<ID>_URL` 连接串 | 只在 `external.py` 内 `os.getenv` 读取，不写入任何 prompt 或工具返回值 |
| `LLM_API_KEY` / `IMAGE_API_KEY` / `JWT_SECRET` / `PLATFORM_API_KEYS` | 只存在于 `settings` 与 SDK 调用参数，无拼接进 prompt 的路径 |
| 微信 `openid` / 第三方原始用户 ID | 入库前即哈希为 `user_id`（`auth.py:136`、`:166`） |
| 平台库敏感列原文 | `_redact()` 脱敏（`external.py:95-101`） |

**存储边界**：

- 会话/消息/DIY 方案/生图任务存内部 PostgreSQL（`flora_agent`），**不落任何平台商品或订单**。
- 生图与贺卡产物写 `data/generated/`（宿主机 `./data` 卷挂载，已被 `.gitignore`）；`IMAGE_PUBLIC_BASE_URL` 为空时对外是相对路径，宿主前端需自行拼接域名。
- 监控埋点只存 `user_id`（派生值）、`platform_id`、耗时、状态、工具名，**不存消息正文**。
