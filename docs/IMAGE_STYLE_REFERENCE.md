# 店铺风格参考生图

## 当前实现

当会话有 `shop_id` 时，生图前会从该店当前可访问的在售商品摘要中提取：

- 风格词：韩式、自然、北欧、法式、复古、现代、简约、奶油、轻奢。
- 颜色词：白、绿、粉、红、香槟、紫、黄、橙、蓝。
- 包装词：雾面纸、牛皮纸、礼盒、花篮、手提袋、丝带。
- 近期商品名称样本。

这些信号会追加到生图 prompt，要求模型只借鉴店铺近期的构图、留白、包装质感和摄影语言，严格保持当前 DIY 方案的花材、支数、配色和包装，不复制某个商品。

## 当前没有实现的部分

现有 Qwen 文生图请求只传文本 prompt，当前实现**没有把商品图片作为视觉输入**，因此不能称为真正的参考图学习或图像风格迁移。店铺商品图只作为下一阶段的输入候选来源。

真正使用参考图需要：

1. 供应商支持多图/参考图输入（例如 image-edit 或 image-reference 模型）。
2. 服务端下载图片、校验公网地址、大小、MIME 和数量。
3. 图像参考与方案事实分离：参考图只影响构图/质感，不允许替换花材和支数。
4. 参考图不可用时自动回退文本生图。
5. 评测“风格相似度、花材准确率、支数一致性、旧风格回退率”。

## 下一阶段实施契约

建议新增 provider 能力声明，而不是根据模型名称猜测：

```python
ImageProviderCapabilities(
    supports_reference_images=True,
    max_reference_images=3,
    accepts='data_url',  # 或 provider 规定的公网 URL
)
```

参考图流程：

```text
平台商品查询
  ↓
筛选当前店铺近期、可公开读取的 1～3 张图片
  ↓
服务端下载并校验 scheme / DNS / MIME / 文件大小 / 像素尺寸
  ↓
必要时转 data URL 或对象存储临时 URL
  ↓
调用明确声明支持参考图的 image provider
  ↓
结果下载、持久化、任务完成
```

安全要求：

- 不把平台私有图片 URL、鉴权 Header 或用户订单字段传给不支持的 provider。
- 禁止内网、回环、云元数据地址；限制每图大小、总大小和数量。
- 参考图只作为风格条件，当前方案 `design` 是权威事实。
- 参考图下载失败、供应商不支持、内容审核失败，都回退文本生图并记录原因。
- 不以“参考图已生效”作为用户文案，除非 provider 返回成功且日志记录输入模式。

评测至少包含：参考图风格相似度、方案花材召回、支数一致性、包装一致性、图片失败率和额外耗时。

## 为什么先做文本风格画像

它不需要新增供应商、不把第三方图片上传给外部模型，能先解决“当前店铺商品语言与生图风格脱节”的问题；同时保留明确的回退路径，避免图片参考链路失败时阻断生图。
