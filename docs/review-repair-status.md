# 1.4.1 源码审阅修复状态（未部署）

本页记录的是当前源码候选的实现/验证范围，不代表生产服务器、H5、商家后台已更新。基线为 `9b84dbb793f8641b3eddccbdf1a85bfe19baeccd`；仍需 Linux CI、部署方配置与独立验收。

## 已在源码修复

- `.env.example` 不再附可直接用的 JWT 签名占位串；非本地环境要求 32 字符以上且拒绝常见公开占位符，强制认证、PostgreSQL 和明确 CORS 域名。字符长度和占位符检测无法证明密钥确系随机生成，部署方必须自行生成并保管。
- `proven` 知识索引使用同一次读取的记录与向量/embedding，记录增删、修改和换序时重新计算；颜色知识可检索，不再声称本地具有实际为空的商家智库。
- 离线评测校验器从实际声明的工具/UI/意图提取允许值，非法字段或空套件返回非零；现有评测集 12 条可通过。根目录 `verify.py` 检查失败返回非零；增加 Python 3.12 + PostgreSQL CI 配置（GitHub 远端尚未运行）。
- 工具异常只返回固定错误码，不把内部异常文本放入模型上下文；单个/延迟工具路径也有异常边界。提示词不再建议不存在的订单实体和商家知识域；体验版禁止交易承诺的规则优先。养护路由与工具范围共享识别规则。
- `/chat` 单消息最多 8000 字符；身份签发接口在进程内按 TCP 对端限流；匿名体验启动时必须配置 Redis、正数全局及单用户每日 token 预算、启用聊天限流和正数 IP 额度。匿名预算 Redis 读取失败时拒绝匿名模型调用。
- 随包 Nginx 按其真实 TCP 对端 IP 对匿名签发、其他认证和体验聊天各自限流。应用不信任客户端自行填写的转发 IP 头；经代理时应用聚合兜底额度需按代理总流量另行设置，且公开流量必须经过网关。

- 对话内的偏好记忆、商品名称、方案文本在 system prompt 中作为 JSON 引用数据并明确不具指令权限；这是纵深防御，不等于消灭提示词注入风险。通知/提醒 API 把完整的同步数据库事务交给工作线程；聊天 API 的调用/工具监控日志也从事件循环移至工作线程，并显式传递日志 ID。会话存储等数据库路径仍未全面改为异步。
- 按选定的 90 天策略增加**手动**留存脚本：默认只预览；加 `--apply` 才会在一个事务里删除已关闭工单、已完成/取消提醒、已读通知、闲置会话和过期日志，不删除开放事项与未读通知。无定时删除任务；见 [留存政策](retention-policy.md)。

## 尚未完成的外部/架构前提

1. 用户决定把匿名入口放在隔离体验实例，但**没有选定每日 token 额度**。此源码不设置臆测额度；未配正数拒绝启动。现行 Redis 预算是请求前检查、调用后累计，允许并发超额，不是严格、原子化的费用硬上限。曾讨论预留/结算实现，但用户已决定**现阶段暂缓**；在费用风险另行解决前，不得把它当作已完成的成本承诺。

3. CI 工作流尚需在代码托管端运行并验证 PostgreSQL 集成；Nginx 配置尚需在真实 Linux 入口执行 `nginx -t`。本地 pytest 通过不等于外部环境通过。
4. H5 凭据签发、商家投递、真实交易、对外通知推送及生产部署仍属接入方或部署方工作；本仓库未声称已具备这些能力。数据库异步阻塞与同步 Redis 预算计量的边界还需后续架构处理。
