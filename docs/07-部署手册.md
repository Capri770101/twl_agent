# 07 · 部署手册

更新：2026-09-29。适用于当前仓库 Compose；源码与验收范围见 [DELIVERY](../DELIVERY.md)，私密配置见 [CONFIGURATION](CONFIGURATION.md)。不假定历史服务器、域名或证书仍有效。

## 环境与服务

Linux + Docker Engine / Compose v2；构建镜像使用 Python 3.12，内部数据库 PostgreSQL 16。需要模型服务网络出口，使用真实平台数据时另需业务接口或只读数据库网络权限。

| 服务 | profile | 入口/存储 |
|---|---|---|
| postgres | 默认 | 容器内 5432，`pgdata` 卷 |
| agent | 默认 | 宿主 `127.0.0.1:8000`，`.env`、`./data:/app/data` |
| nginx | nginx | 80/443，域名和证书由部署方提供 |
| dashboard | nginx | 容器内 80，经 nginx `/dashboard/` |
| postgres-demo | demo | 独立 `pgdata_demo` 卷 |
| agent-demo | demo | 宿主 `127.0.0.1:8010` → 容器 8000，`.env.demo`、`data_demo/` |

默认两服务。agent/PostgreSQL 有健康检查；nginx/dashboard 以运行状态和 HTTP 验证，不能要求所有容器都显示 healthy。

## 首次部署

1. 取得指定提交的源码，记录 commit；准备 `.env` 与 `.env.demo`，模板分别是根 `.env.example` 和 `deploy/env.demo.example`。
2. 填写 `POSTGRES_PASSWORD`、`DEMO_POSTGRES_PASSWORD`。Compose 对完整文件插值，不要认为关闭 demo profile 就能省略所有 demo 配置。演示启用时其连接串密码与演示库密码一致。
3. 填写内部 PostgreSQL、JWT、平台 Key、模型及明确 CORS；真实出图、语音和商品源按配置清单补齐。
4. 本开发快照保持 `CUSTOMER_SERVICE_ENABLED=false`。实际数据和账号迁移前备份原库及文件。

```bash
docker compose config --quiet
docker compose up -d --build postgres agent
docker compose ps
curl -fsS http://127.0.0.1:8000/health
```

`/health` 返回 `{"status":"ok"}`。应用启动会调用 `init_db()` 创建当前全部表/索引，账号需对应权限；若由 DBA 维护，请按 `backend/storage/db.py` 完整 schema 准备，不只执行旧图片任务迁移。

## HTTPS、监控与演示

先修改 `deploy/nginx.conf` 的真实域名/路由，准备 `deploy/certs/fullchain.pem` 和 `privkey.pem`；确认 DNS、证书与防火墙。历史 `api.tiaowulan.com` 不是本轮验收入口。

```bash
docker compose --profile nginx up -d --build agent nginx dashboard
docker compose --profile nginx exec nginx nginx -t
# 使用实际域名检查 /health、/dashboard/、SSE 以及 /generated/。
```

监控配置 `DASHBOARD_API_KEY`，未配置接口返回 503。nginx 使用 Docker DNS resolver 和变量上游，避免容器重建后继续访问旧 IP。

```bash
# 已准备独立 .env.demo
docker compose --profile demo up -d --build postgres-demo agent-demo
curl -fsS http://127.0.0.1:8010/health
# 仅停止演示，不使用可能同时停止主服务的 compose down
docker compose --profile demo stop agent-demo postgres-demo
```

## 更新方式

| 改动 | 操作 |
|---|---|
| Python/知识库/依赖 | `docker compose up -d --build --no-deps agent` |
| 主服务 `.env` | `docker compose up -d --force-recreate --no-deps agent` |
| 演示 `.env.demo` | `docker compose --profile demo up -d --force-recreate --no-deps agent-demo` |
| dashboard | `docker compose --profile nginx up -d --build --no-deps dashboard` |
| nginx 配置/证书 | `docker compose --profile nginx up -d --force-recreate --no-deps nginx`，再 `nginx -t` 和 HTTP 检查 |
| demo 静态页 | bind mount 的 `demo/` 文件更新后浏览器刷新 |

**`restart` 不加载新的环境变量**；代码变更需要构建新镜像。nginx 单文件挂载被宿主替换时，单纯 reload 可能仍读旧 inode，因此使用 recreate 重新建立挂载。

## 数据、备份与回滚

- 备份 PostgreSQL、`.env`、证书、`data/generated/`，记录旧镜像 ID、Compose 项目名和卷名。
- 更换部署目录时不要无意更换 Compose 项目名而创建空数据库卷；确认卷挂载和固定容器名冲突后再切换。
- `IMAGE_PUBLIC_BASE_URL` 只影响 URL 拼接；当前没有自动 OSS 上传。外置 CDN 须单独实现回源/同步。
- 回滚用之前记录的源码或镜像及匹配配置；客户服务先关开关。保留新增监控表，不盲目回滚整库。
- 通过 [测试与验收](09-测试与验收.md) 后再记录正式发布。健康检查不是模型、订单或语音验收。
