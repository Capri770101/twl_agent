# 出图（效果图）对接说明 —— 小程序复用 H5 花艺顾问能力

> 编写时间：2026-09-21｜面向：小程序前端 + 服务端同事
> 目的：把 H5「花艺顾问」已经跑通的**效果图功能**完整搬到小程序。
> 所有示例均已**脱敏**（无密钥、无真实用户 ID、无生产任务号）。
> 关联：`docs/小程序AI页-前端改造交接单.md`（卡片渲染与字段契约）、`docs/05-前端对接契约.md`（§4.1 图片拼域名 / §3 SSE）

---

## 0. 一句话结论

**出图不是一条独立接口，就是普通对话的一轮。** 全链路只有两步：

1. `POST /chat` —— 模型自己调用生图工具，响应里下发 `task_id` + `poll`；
2. `GET /tasks/{task_id}` —— 前端轮询到 `status=done`，取 `result_url`。

所以：**不需要额外调用任何"提交生图任务"的接口**，也**不需要平台侧新增路由**。
「**小程序现在调用的 `/chat` 已经完整支持出图**」，缺的只是前端把 `data` 里的 `task_id`/`poll` 读出来并轮询（详见 §7）。

## 1. 完整时序

```
用户：给这个方案生成一张效果图
  │
  ├─(1) POST /chat  {message, user_id, session_id, shop_id}
  │      → data.ui = "plan_card"，data.plans[...] 是方案本体，
  │        同时 data 顶层多出 task_id / poll        ← 生图任务信息
  │
  ├─(2) 前端拿 data.poll 轮询  GET /tasks/{task_id}     （必须带 Bearer，见 §6）
  │      → status: processing → 继续轮询（H5 用 3.5s 间隔）
  │
  ├─(3) status: "done" → 返回体里出现 result_url
  │      → 拼域名后 <image src="...">   （见 §5）
  │
  └─(4) status: "failed" → 读 error 字段，提示"重新生成"

（流式模式下第 (1) 步换成 POST /chat/stream，task_id 从 card 事件里拿，见 §3.2）
```

## 2. 聊天接口返回示例（脱敏）

### 2.1 非流式 `POST /chat`（小程序当前使用的路径）

> 说明：小程序不直接调平台，而是走宿主后端 `POST /v1/ai/flower-advisor`，
> 后者原样透传平台响应（`res.json({code:0, data: result.body})`）→ **字段不会丢**。

**请求**

```http
POST {平台地址}/chat
Authorization: Bearer <JWT>
X-API-Key: <宿主后端注入，前端不接触>
Content-Type: application/json

{
  "message": "给这个方案生成一张效果图",
  "user_id": "<业务侧用户标识>",
  "session_id": "<上一轮返回的 session_id，首轮可省略>",
  "shop_id": "<店铺 id，如 sXXX>"
}
```

**响应（情况 A：方案卡 + 生图任务并存 —— 最常见）**

```json
{
  "user_id": "<业务侧用户标识>",
  "reply": "效果图我已经在生成啦，大概需要十几秒，稍等一下～",
  "ui": "plan_card",
  "data": {
    "task_id": "9f2c41ab77de4350",
    "poll": "/tasks/9f2c41ab77de4350",
    "plans": [
      {
        "plan_id": "DIY_3b18c2",
        "name": "粉黛温情",
        "diy": true,
        "estimated_price": "约 296 元",
        "desc": "粉康乃馨 ×23、粉玫瑰 ×22",
        "effect_image_url": "",
        "design": { "main_flowers": [], "fillers": [], "foliage": [] },
        "budget_breakdown": { "items": [], "total_estimate": 296 },
        "copy_text": "【定制花束需求单】..."
      }
    ]
  },
  "action": { "type": "show_plan", "payload": { "reply": "..." } },
  "tool_calls": ["generate_effect_image"],
  "session_id": "a1b2c3d4e5f6478890abcdef12345678",
  "stage": "view_plan",
  "products": [{ "plan_id": "DIY_3b18c2", "name": "粉黛温情", "price_yuan": null, "image": null, "stock": null }],
  "ai_generated": true,
  "content_disclosure": "本内容由 AI 生成，仅供参考"

```

🔴 **要点：`task_id` / `poll` 挂在 `data` 的顶层**（与 `plans` 平级），**不是**一张独立的 `image_task` 卡片。
这是实测结论，H5 的代码注释里也写着同一个坑（`H5/src/pages/Advisor.vue` 约 591 行）。
所以判据要放宽成「`data` 里出现 `poll` / `task_id` / `result_url` 任意一个」。

**响应（情况 B：只有一个生图任务、没有卡片可展示）**

```json
{
  "reply": "效果图正在生成中，稍等一下就好～",
  "ui": "image_task",
  "data": { "task_id": "9f2c41ab77de4350", "poll": "/tasks/9f2c41ab77de4350" }
}
```

**响应（情况 C：任务极快已完成，同一轮就已经有图）**

```json
{
  "ui": "image_task",
  "data": {
    "task_id": "9f2c41ab77de4350",
    "poll": "/tasks/9f2c41ab77de4350",
    "result_url": "/generated/9f2c41ab77de4350.png"
  }
}
```

> 情况 C 下也**可以直接出图、不必轮询**（H5 就是这么做的：先看 `result_url`，没有再轮询）。
> 但它不是常态 —— 真实生图要十几秒，绝大多数是情况 A/B。

### 2.2 顶层 `products` 是摘要，**不要**拿它渲染商品卡

`data.products[0]` 的真实字段只有 `plan_id` / `name` / `price_yuan` / `image` / `stock`
（`id` 与 `price` 恒为 `null`）。真正的商品数据在 `data.data.plans`。
（细节见 `docs/小程序AI页-前端改造交接单.md` §1.1。）

## 3. 流式模式（可选，第二步再做）

### 3.1 `POST /chat/stream` 的 SSE 事件

| `event` | 含义 | 前端动作 |
|---|---|---|
| `text_delta` | 逐字增量 | 追加到气泡 |
| `text` | 整段兜底（**只在一次都没推过时**才发） | 覆盖气泡 |
| `text_rollback` | **撤回已推文字**（模型中途改去调工具） | 清空气泡，否则残留内部独白 |
| `card` | 卡片数据 | `data.ui` + `data.data`，**生图任务在这里**（见下） |
| `tool_call` | 工具名 | 显示「正在查询…」进度 |
| `done` | 终稿 | `reply` 是**权威终稿**，要覆盖已累加的文字；`session_id` 存下来回传 |
| `error` | 错误 | 提示重试 |

### 3.2 流式下的生图任务长这样

```
event: card
data: {"ui":"plan_card","data":{"task_id":"9f2c41ab77de4350","poll":"/tasks/9f2c41ab77de4350","plans":[...]}}
```

判据与 §2.1 一致：**`data` 里出现 `poll` / `task_id` / `result_url` 就启动轮询**。

> ⚠️ 小程序**不支持 SSE**。要做流式只能用 `wx.request({ enableChunked: true })` + `onChunkReceived`
> 自己解析 SSE 报文（含 UTF-8 手动解码 + 半包缓冲），细节见 `docs/05-前端对接契约.md` §3。
> **但出图与流式无关 —— 先按非流式做，功能不缺失。**

## 4. 任务状态查询

```http
GET {平台地址}/tasks/{task_id}
Authorization: Bearer <JWT>          ← 必须，见 §6
Accept: application/json
```

**响应字段**

```json
{
  "task_id": "9f2c41ab77de4350",
  "user_id": "<业务侧用户标识>",
  "status": "processing",
  "prompt": "粉康乃馨与粉玫瑰为主的花束，柔光……",
  "result_url": "",
  "error": "",
  "created_at": "2026-09-21 02:15:33",
  "updated_at": "2026-09-21 02:15:33"
}
```

**`status` 取值（🔴 终态是 `done`，不是 `succeeded`）**

| 值 | 含义 | 前端动作 |
|---|---|---|
| `processing` | 生成中 | 继续轮询 |
| **`done`** | **成功** | **取 `result_url` 展示，停止轮询** |
| `failed` | 失败 | 读 `error` 提示，可给「重新生成」按钮 |
| `not_found` | 任务不存在**或不属于当前用户** | 停止轮询，按失败处理（**不要**当异常抛给用户） |

**轮询参数建议（与 H5 现网一致）**

- 间隔 **3.5s**，最多 **40 次**（≈140s）
- 整体加 150s 的 `AbortController` 兜底，避免请求永远挂着
- 首次轮询前先看响应里有没有现成的 `result_url`，有就直接展示

> 服务端保证：`processing` 超过 **300s** 会被就地判为 `failed`（`error: "生图超时，请重新生成"`），
> 所以**前端一定能拿到终态**，不会永远卡在「生成中」。

## 5. 完成后的图片字段

| 场景 | 字段 |
|---|---|
| 轮询命中 | `GET /tasks/{id}` 的 **`result_url`** |
| 聊天响应同轮已完成 | `plan_card.data.result_url`（无卡时）或 `plans[i].effect_image_url` |
| 电子贺卡（同步，不用轮询） | `greeting_card.data.image_url` |

🔴 **相对路径必须拼域名**。生产环境 `IMAGE_PUBLIC_BASE_URL` 为空，后端返回的是
`/generated/9f2c41ab77de4350.png`，直接塞进 `<image src>` 会打到小程序自己的域名上 → 图裂。

```js
// 幂等：可被多层重复调用，不会拼成 /xxx/xxx/generated/a.png
const BASE = 'https://api.tiaowulan.com'   // 或宿主自己的静态资源代理域名
const absImg = (u) => (!u ? '' : (/^https?:/i.test(u) ? u : BASE + u))
```

> ⚠️ H5 仓库里的 `src/utils/agentAsset.js` 是**已跑通的幂等实现**，小程序侧可直接照搬逻辑
> （它是纯函数、不含 DOM），别自己重写 —— 重写最容易丢的就是「幂等」这一条。

## 6. 图片地址会不会过期？取图要不要鉴权？

### 6.1 图片**永不过期**（但务必理解为什么）

链路是这样的：

```
阿里云百炼生图 → 返回一个【带签名的 OSS 临时地址，有 Expires，会过期】
        ↓ 后端立刻下载图片字节（绝不把该 URL 下发给前端）
        ↓ 写入自己的磁盘 data/generated/{task_id}.png
        ↓ 下发自己的地址 /generated/{task_id}.png
```

所以前端拿到的是**我们自己托管的永久静态地址**，nginx 上带 `Cache-Control: public, max-age=2592000, immutable`（30 天）。

> ⚠️ 与上游厂商的 OSS 地址**必须区分开**：那个是**有时效**的，直接存起来给前端用会 403。
> 后端已做「立即转存」，接入方不需要关心，但**别自己去找上游地址**。

### 6.2 取图**不需要鉴权**，查任务**需要**

| 请求 | 鉴权 | 说明 |
|---|---|---|
| `GET /generated/{task_id}.png` | ❌ **不需要** | 公开静态资源，无任何凭据。路径是 16 位随机 hex，不可枚举 |
| `GET /tasks/{task_id}` | ✅ **必须 `Bearer <JWT>`** | 实测**只带 X-API-Key 会 401**（报「需要 Bearer 登录凭证」） |
| `POST /chat`、`/chat/stream` | ✅ 必须 | 同上 |

**归属校验**：任务按 `user_id` 过滤，查别人的任务一律返回 `not_found`（不区分"不存在"与"不是你的"）。

> 取值时 `X-API-Key` 由**宿主后端注入**，前端/小程序**不应该**持有平台 Key。

## 7. 小程序当前调用的 `/chat` 支持出图吗？

**支持，且与流式路径完全同源。** 三条依据：

1. **生图是服务端工具调用**（`generate_effect_image`），与传输方式（流式/非流式）无关；
2. 平台的 UI 决议逻辑在两条路径**共用同一段代码**：非流式 `POST /chat` 同样会把
   `task_id` / `poll` / `result_url` 组装进 `ui` + `data` 再返回；
3. 小程序走的是宿主后端 `POST /v1/ai/flower-advisor`，它 `res.json({code:0, data: result.body})`
   **原样透传**平台响应 → 字段不会被吃掉。

**所以小程序侧缺的只有三件事**：

- ① 把 `data.task_id` / `data.poll` 读出来（**注意两个位置**：`data` 顶层，以及 `plan_card.data` 内层）；
- ② 轮询任务状态；
- ③ 图片相对路径拼域名。

**⚠️ 唯一需要服务端配合的一点**：`/tasks/{task_id}` 需要 **Bearer**，而平台 JWT 只应由宿主后端持有 →
宿主后端需要补一条转发（H5 的做法是**通用透明反代**，见 §8.3）：

```
GET /v1/ai/flower-advisor/task/:taskId   →  转发到平台 GET /tasks/{taskId}（带 Bearer）
```

> 💡 参考：H5 的 `/agent/*` 就是一条**透明反代**（`H5/deploy/server.cjs`），
> 平台 Key 只在服务端注入、`/tasks/*` 不计入限流桶（否则 3.5s 一次的轮询会把限流打满）。
> 小程序后端照这个模式做一条即可。

## 8. H5 对应调用代码（可直接参照）

### 8.1 轮询：`H5/src/mock/api.js::pollAgentTask`

```js
export async function pollAgentTask(pollUrl, cb = {}) {
  const onImage = cb.onImage, onStatus = cb.onStatus
  if (!pollUrl) return null
  // 平台给的是相对路径（/tasks/xxx），必须经 apiBase 转发（以便由服务端注入 Key）
  const url = String(pollUrl).startsWith('http') ? String(pollUrl) : (AGENT_CONFIG.apiBase + pollUrl)
  // ⚠️ /tasks/{id} 需要 Bearer；只带 X-API-Key 会 401
  const token = await ensureAgentToken()
  const ctrl = new AbortController()
  const timer = setTimeout(() => ctrl.abort(), 150000)
  try {
    for (let i = 0; i < 40; i++) {            // 40 × 3.5s ≈ 140s
      let d = null
      try {
        const res = await fetch(url, {
          headers: { Accept: 'application/json', Authorization: 'Bearer ' + token },
          signal: ctrl.signal
        })
        if (!res.ok) break
        d = await res.json()
      } catch (e) { break }
      if (!d || typeof d !== 'object') break

      const status = String(d.status || '').toLowerCase()
      const raw = d.result_url || d.image_url || d.effect_image_url || d.url || ''
      const img = normalizeAgentAssetUrl(raw)     // 幂等拼域名
      if (img && onImage) onImage(img)
      if (status === 'failed' || status === 'error') { onStatus && onStatus('failed', d.error || ''); break }
      if (status === 'done' || status === 'completed' || status === 'succeeded') { onStatus && onStatus('done', ''); break }
      onStatus && onStatus(status || 'processing', '')
      await new Promise(r => setTimeout(r, 3500))
    }
  } catch (e) { /* 轮询失败静默：出图失败不该影响对话本身 */ }
  finally { clearTimeout(timer) }
  return null
}
```

### 8.2 触发时机与回填：`H5/src/pages/Advisor.vue`

```js
// ① 收到 card 事件时判断「有没有生图任务」——注意判据要放宽
if (data && (data.poll || data.task_id || data.result_url)) startImagePoll(cur(), data)

// ② 轮询结果回填：消息级的图要**同时**写进方案卡封面，否则卡片会一直停在「生成中」
function injectImageToCards(msg, img) {
  for (const c of (msg.cards || [])) {
    if (c.ui === 'diy_plan_card') c.data.effect_image_url = img
    if (c.ui === 'image_task')    c.data.result_url = img
    if (c.ui === 'plan_card') for (const p of c.data.plans) if (p.diy) p.effect_image_url = img
  }
}

// ③ 刷新/切会话后，把「已提交但还没出图」的任务接着轮询（poll 已随消息本地落盘）
function resumeImageTasks(list) {
  for (const m of (list || [])) if (m && m.poll && !m.image) startImagePoll(m)
}
```

## 9. 小程序改造清单（最小可交付）

- [ ] **1. 读任务信息**：`data.task_id` / `data.poll`（`data` 顶层）+ `plan_card.data` 内层两处都读
- [ ] **2. 轮询**：`wx.request` GET `/tasks/{id}`，带 Bearer，3.5s × 最多 40 次
- [ ] **3. 状态机**：`processing` → 骨架 + 计时；`done` → 出图；`failed` → 提示 + 重试；`not_found` → 按失败处理
- [ ] **4. 拼域名**：幂等函数（直接搬 `agentAsset.js` 的逻辑），相对路径必须拼
- [ ] **5. 回填位置**：图要写进 **DIY 卡封面**，不是只渲染在消息末尾
- [ ] **6. 加载兜底**：`<image>` 用 `mode="widthFix"` + `binderror`，失败不要留白块
- [ ] **7. 服务端**：补 `/tasks/{id}` 的 Bearer 转发（见 §7）
- [ ] **8. 打卡片后**：DIY 卡出口是「生成效果图 / 复制用料清单」，**不是「立即购买」**

**验证用的触发语**（照这个说就能复现）：

| 想要的状态 | 说什么 |
|---|---|
| 出图（有 DIY 卡） | 先 `我想用香槟玫瑰和洋桔梗自己搭配一束，预算200`，再说 `给我看看效果图` |
| 出图（无卡） | 说 `给这个方案生成一张效果图`（无方案时会返回未找到方案的错误提示） |
| 失败态 | 多次触发直至排队满 → `error: 生图排队已满，请稍后重试` |

> ⏱ 实测生图**通常十几秒，慢时 >40s**，前端要有进度与计时，别让用户对着白屏等。
