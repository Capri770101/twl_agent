## 0. 接入前提（先做完，否则后面全是白工）

### 0.1 架构总览：全流量服务器代理（当前采用）

> **本清单按「全流量代理」编写**：小程序**不直连** `api.tiaowulan.com`，
> 所有请求都打到**你们自己的后端域名**，由你们后端转发到 flora。
> 密钥与 JWT 对外皆不可见，是本方案最安全的接法。

```
小程序 ──(只认你们域名)──> 你们后端 ──(服务端转发)──> api.tiaowulan.com
                              │
                              └─ 持有 X-API-Key，负责换 token 与透传 JWT
```

由此带来三条硬约束：

1. **小程序后台「request 合法域名」只配你们自己的域名**，不需要配 `api.tiaowulan.com`。
2. **平台密钥 `X-API-Key` 只存在于你们后端**，绝不进小程序。
3. **下面第 1~3 项里出现的 `api.tiaowulan.com/xxx` 是 flora 侧的原始接口与路径**，
   供你们后端配置转发规则用；小程序侧请替换成你们自己的代理域名 + 路径。

> **唯一例外**：第 2.4 节的生成图（`/generated/xxx.png`）是公开静态资源、不含任何凭据，
> 可让小程序直连取图，也可一并走代理——见该节说明。

### 0.2 域名白名单

小程序后台 → 开发管理 → 开发设置 → **服务器域名 → request 合法域名**，添加**你们自己的后端域名**（HTTPS + 已备案）。

### 0.3 鉴权 —— ⚠️ 平台密钥绝不能写进小程序

`PLATFORM_API_KEYS` 是服务端密钥，**放进小程序等于把整个智能体后门公开**。正确链路：

```
小程序(微信登录态) → 你们自己的后端 →(X-API-Key)→ 我们的 /auth/token → JWT → 下发小程序
```

换取 token（**这一步由你们后端做**）：

```http
POST https://api.tiaowulan.com/auth/token
X-API-Key: <平台密钥，仅你们服务端持有>
Content-Type: application/json

{ "external_user_id": "用户在你方的唯一ID（如微信openid）" }
```

响应：

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer",
  "user_id": "wxmini_be1ed470939b8215110d849c",
  "platform_id": "wxmini"
}
```

⚠️ **`user_id` 必须用这里返回的派生值（`wxmini_xxx`）**，后续所有请求都要带上它；自己编一个或传 openid 会返回 **403**。

之后每个业务请求都带：`Authorization: Bearer <JWT>`。
**你们后端转发时必须原样透传这个头**，漏传会得到 401。

## 0.4 代理层必读：SSE 流式转发配置

> **这一段决定第 1 项（流式输出）能不能真正生效**，直连架构下不需要，全流量代理下必看。
> 配错的话，流式会退化成「转圈几秒 → 整段话一次性弹出」，等于第 1 项白做。

以 nginx 为例，转发 `/chat/stream` 的 location 至少要这样：

```nginx
location /<你的代理路径>/chat/stream {
    proxy_pass https://api.tiaowulan.com/chat/stream;

    # ① 关掉响应缓冲：否则 SSE 会被攒着一起发，流式失效
    proxy_buffering off;
    proxy_cache off;

    # ② 长连接超时要调大：SSE 是长连接，默认 60s 会在生成过程中被掐断
    proxy_read_timeout 300s;
    proxy_send_timeout 300s;

    # ③ 关闭 gzip：压缩会引入缓冲，同样让流式变成一次性
    gzip off;

    # ④ 透传鉴权与 SSE 所需头
    proxy_set_header Authorization $http_authorization;
    proxy_set_header Connection '';
    proxy_http_version 1.1;
    chunked_transfer_encoding on;
}
```

其他代理技术（Node / Java / Go 网关）同理，核心是同一条：**不要缓冲、不要压缩、超时够长、透传 Authorization**。

flora 侧已经在响应里带了 `X-Accel-Buffering: no` 和 `Cache-Control: no-cache`，nginx 会自动遵守；但如果你们中间还有一层 CDN 或网关，那一层同样要关缓冲。

## 1. 流式输出（后端已做好，前端还没接）

### 1.1 现状（已核实）
线上 24 小时真实统计：

| 端点 | 调用次数 |
|---|---|
| `POST /chat/stream`（流式） | **0 次** |
| `POST /chat`（非流式） | 5 次 |

也就是说，用户现在看到的是**「转圈 5 秒 → 整段话一次性弹出」**。

### 1.2 要做的：把 `/chat` 换成 `/chat/stream`

请求参数**完全一样**，只改路径。

> ⚠️ **全流量代理下**：下面这段是 **flora 侧原始接口**，给**你们后端**配转发用。
> 小程序侧请求的是 `https://<你们域名>/<代理路径>/chat/stream`，由后端转发到这里。
> 转发配置见 **0.4 节**（SSE 必须关缓冲，否则流式失效）。

```http
POST https://api.tiaowulan.com/chat/stream
Authorization: Bearer <JWT>
Content-Type: application/json

{
  "user_id": "wxmini_be1ed470939b8215110d849c",
  "message": "我想送花给朋友",
  "session_id": "上一轮返回的会话ID（首次可空，多轮必须传）",
  "location": { "lat": 22.55, "lng": 114.06 },
  "shop_id": "从店铺页进入时才传，一般可空"
}
```

> `location` 可选，传了才能按距离推荐店铺；`shop_id` 只有从指定店铺页进入时才传。

### 1.3 SSE 事件格式

```
event: tool_call
data: {"name":"platform_db_query_entity","status":"ok"}

event: text
data: {"content":"这几束都很适合送朋友……"}

event: card
data: {"ui":"plan_card","data":{"plans":[...]}}

event: done
data: {"session_id":"fee6e395a3db41a0acaec1228bcb95e1"}
```

| 事件 | 含义 | 前端该做什么 |
|---|---|---|
| `tool_call` | 智能体正在查数据 | 显示「正在查询…」——**强烈建议做**，能极大改善等待体感 |
| `text` | 文字片段 | **追加**到当前气泡（不是替换） |
| `card` | 结构化卡片 | 按 `ui` 字段渲染对应组件（见第 2 节） |
| `done` | 本轮结束 | **保存 `session_id`**，下一轮必须回传 |
| `error` | 出错 | 展示错误提示，保留重试入口 |

### 1.4 微信小程序实现要点（最容易踩坑的地方）

小程序**没有 `EventSource`**，必须用分块传输：

```js
const task = wx.request({
  url: 'https://<你们域名>/<代理路径>/chat/stream',   // ← 全流量代理：填你们自己的域名
  method: 'POST',
  enableChunked: true,                 // ← 关键：开启分块接收
  header: {
    'Authorization': 'Bearer ' + token,
    'Content-Type': 'application/json',
  },
  data: { user_id, message, session_id },
})

let buf = ''
task.onChunkReceived((res) => {
  const chunk = decodeUTF8(res.data)   // ArrayBuffer → 字符串
  buf += chunk
  // 必须缓冲后按 "\n\n" 切出完整事件，再解析 event: / data: 行
})
```

**四个必看坑位**：

1. `onChunkReceived` 给的是 **ArrayBuffer**，要自己 UTF-8 解码（`TextDecoder`；低版本基础库需 polyfill）
2. **中文会被切在两个 chunk 中间** —— 必须先缓冲、再按 `\n\n` 切分，绝不能拿到一块就 `JSON.parse`
3. `success` 回调在**流结束时**才触发，里面是完整内容 —— 别和 `onChunkReceived` 重复渲染
4. 老基础库/部分真机不支持 `enableChunked` → **降级回 `/chat`**（一次性返回），保证功能不挂

### 1.5 验收标准
- [ ] 文字一段段往外冒，不是等几秒后整段弹出
- [ ] 过程中能看到「正在查询…」之类的中间状态
- [ ] 结束时拿到 `session_id` 并本地保存
- [ ] 不支持分块的机型能自动降级，不白屏

## 3. 历史对话保留 & 会话管理

### 3.1 后端接口已全部就绪，**不需要后端再开发**

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/conversations?user_id=xxx` | 会话列表 |
| `GET` | `/conversations/{session_id}/messages?user_id=xxx&limit=50` | 历史消息（limit 上限 200） |
| `POST` | `/conversations` | 新建会话 |
| `POST` | `/chat/reset` | 清空 / 删除会话 |

全部需带 `Authorization: Bearer <JWT>`，且 `user_id` 必须与 token 中的一致（不一致 → 403）。

### 3.2 会话列表返回（真实结构）

```json
[
  {
    "session_id": "fee6e395a3db41a0acaec1228bcb95e1",
    "user_id": "wxmini_241f6dc5593f5051c7bf96ed",
    "stage": "analyze",
    "title": "你好",
    "preview": "你好",
    "shop_id": "",
    "updated_at": "2026-09-07T01:50:21+00:00"
  }
]
```

### 3.3 历史消息返回（真实结构）

```json
[
  {
    "id": 589,
    "session_id": "fee6e395a3db41a0acaec1228bcb95e1",
    "role": "assistant",
    "content": "你好呀～我是你的专属花艺小助手，帮你把心意变成花。",
    "ui": "\"text\"",
    "created_at": "2026-09-07T01:50:21+00:00"
  },
  {
    "id": 588,
    "session_id": "fee6e395a3db41a0acaec1228bcb95e1",
    "role": "user",
    "content": "你好",
    "ui": null,
    "created_at": "2026-09-07T01:50:21+00:00"
  }
]
```

- `role`：`user` / `assistant`
- ⚠️ **`ui` 是 JSON 字符串**（如 `"text"`、`"plan_card"`），要先 `JSON.parse` 再判断渲染成文本气泡还是卡片
- 历史消息里的卡片，同样按第 2 节的组件渲染（别只渲染纯文本）

### 3.4 ⚠️ 最关键：`session_id` 必须回传

**多轮对话的记忆全靠 `session_id`。** 不传 = 每轮都是新会话 = 用户感觉「这傻子聊上句忘下句」。

正确流程：
1. 首次对话不带 `session_id` → 从 `done` 事件（流式）或响应里拿到 `session_id`，本地存起来
2. **之后每一轮都带上这个 `session_id`**
3. 用户点「新对话」→ 调 `POST /conversations` 新建，或下一轮不带 `session_id`

### 3.5 验收标准
- [ ] 杀掉小程序重进，能看到历史会话列表
- [ ] 点进会话，历史消息渲染正确（**卡片也要渲染出来**，不是只有文字）
- [ ] 在旧会话继续聊，智能体记得之前说过什么
- [ ] 「新对话」「删除会话」可用
