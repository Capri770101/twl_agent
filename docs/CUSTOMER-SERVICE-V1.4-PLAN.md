# 统一客户服务入口：v1.4.0 实施计划

日期：2026-09-28。状态：实施中，首批只读接口本地实现，未发布。配套 H5 目标版本：1.1.0。

## 产品确认记录（2026-09-28）

用户已确认：
1. 首版只读：店铺咨询、本人订单和售后进度；不开放取消、修改或退款办理。
2. 店铺/商品入口继承店铺；首页未指定时询问或展示店铺选择。本人订单可跨店查询，但多笔匹配须用户选择。
3. 公开店铺咨询无需登录；订单/售后必须登录，登录后继续原问题。
4. 暂无确定的人工渠道；后续前端将打通店铺后端，DIY 方案确认订单也经该通道办理。当前只预留能力契约，不将发消息当作接单、报价确认或下单成功。
5. 后续为各店建设独立知识库。首版设计需预留店铺知识来源与隔离，不将未建设知识库标为已完成。

### 店铺通道预留

能力按店铺提供：咨询受理、DIY 报价/可制作确认、订单确认。实际实现前需确定认证方式、店铺标识映射、请求及回执状态、幂等键、超时/撤销和人工承接。必须区分“用户确认方案”“已提交门店”“门店确认可制作/报价”“订单已创建”“已支付”。首版不新增可执行写工具或虚构转接入口。

### 独立店铺知识库设计约束

- 公共花艺知识与店铺专属资料分层；商家政策、营业说明、定制偏好只检索当前确定店铺及允许的公共资料，不拿其他店规则补缺。
- 文档元数据预留 platform_id、shop_id、document_id、version、source、updated_at、effective_from/effective_to、审核/发布状态和适用主题。
- 店铺身份来自服务端校验的上下文；检索过滤在服务端执行，不能仅依赖提示词。订单查询选中其他店订单时需明确切换本次规则查询的店铺，不污染原会话锁店。
- 同店有效已发布规则优先于通用建议；库存、真实价格、订单状态、退款结果以业务接口为准。冲突或缺失时说明不确定，不保证配送/赔付。
- 店铺资料更新需支持审核发布、撤回、版本追踪；索引和缓存按平台/店铺隔离，撤回后不能继续命中旧规则。
- 验收覆盖 A 店不能命中 B 店资料、未选店先澄清、跨店切换、过期/撤回资料、公共知识回退及来源追踪。独立物理库或共享索引强制租户过滤的选型待店铺规模与部署条件明确后确定。

## 1. 目标与版本范围

用户在同一对话页完成店铺咨询、选花定制、订单查询、售后进度查询及养护咨询。登录、选择订单、上传材料、确认操作和支付通过对话内组件或必要的授权页面完成，不强求纯文字操作。

v1.4.0 首版必须交付：可信身份桥接、店铺咨询、我的订单查询、订单详情/可获取的履约状态、售后与退款进度查询、对话内卡片与语音摘要、错误降级、业务监控和验收文档。

后续增量（不冒充 v1.4.0 已交付）：对话内组单与支付承接、取消订单、地址/时间修改、售后申请与图片、催单/人工工单、主动通知。先核实业务 API 再确定 1.5.0 等后续版本范围。不得为凑齐首版绕过授权或直接调用退款审批接口。

## 2. 当前基线与差距

正式文件版本：agent VERSION=1.3.0，H5 package.json=1.0.5；近期功能部署超出这两个标签，发布审计必须同时记录 commit、镜像/构建校验值和部署时间。

已有：DIY/版本恢复/预览任务、语音、结算贺卡、H5 订单及退款相关代码。已核对的接口：

| 业务 | 现有代码入口 | 新版本工作 |
|---|---|---|
| 店铺列表与详情 | H5 server/src/index.js，GET /api/shops、/api/shops/:id | 核对营业/配送字段来源、时区及缺失规则 |
| 我的订单 | server/src/orders.js，GET /api/orders、/:id | 复查账号归属、分页、状态映射，封装只读工具 |
| 取消、退款申请 | 同文件 POST /:id/cancel、/:id/refund | 属后续写操作，先审状态与幂等规则 |
| 商家退款审批 | 同文件 /admin/refund/* | 禁止向客户智能体暴露 |
| 真实用户身份 | server/src/token.js、auth.js | 与 agent 用户身份建立服务端可信映射 |
| 支付与退款结果 | server/src/pay.js、merchantBridge.js | 区分平台状态、商家审核、支付渠道退款；核实可查字段 |

当前 agent 通用数据网关对订单/用户实体的默认限制不能直接放开；新增专用、按账号授权的业务服务适配层。模型不能传入任意 user_id 作为授权依据。

## 3. 业务行为与验收标准

### 店铺咨询
- 支持地址、营业时间、配送范围、费用、预约规则；会话已锁店时默认该店。
- 多店或地址不明确先询问；营业时间缺失不推断正在营业，配送范围没有依据不保证可送。
- 规则资料包含适用店铺、来源、更新时间、有效期；动态字段查询接口，静态政策检索知识库。

### 订单查询
- 未登录先引导登录，完成后续接原问题；公开店铺咨询不强制登录。
- “昨天那一单”按用户时区筛选；有多笔返回候选列表，禁止擅选。
- 摘要包含订单尾号、商品、金额、状态、配送/自提时间及服务端允许的下一步。
- “制作中”不说成“正在配送”；没有骑手定位接口就不能宣称实时追踪。

### 售后进度
- 区分申请已提交、待审核、商家同意/拒绝、退款处理中、退款成功/失败。
- 只有渠道或权威后端状态证明成功，才能说退款成功；不能把商家同意等同到账。
- 无记录、上游超时、无权限和暂不支持是不同结果，不能都回答“没有订单”。

### 后续办理通路
- 查询不需逐项确认；有后果的写操作先产生服务端操作预览，包含目标、费用、可修改字段、有效期。
- 用户确认后重新校验状态、归属、操作预览及幂等键；重复点击/网络重试不重复办理。
- 人工转接必须有真实承接通道与工单回执；未接通时只展示真实联系方式。

## 4. 技术设计

### 身份与服务边界（P0）
1. H5 业务后端验证登录凭据，签发或交换短时效业务授权上下文。
2. agent 校验签名/受众/过期/平台，获取服务端绑定的业务用户，不把凭据塞进模型上下文。
3. 业务查询始终在 H5 后端再次执行订单归属过滤；账号切换清除 token、待续办操作和查询缓存。
4. 服务间凭据仅存后端环境配置；禁止复用公开匿名 external_user_id 换票路径读取私人业务。

### 工具层（拟定名称，非已上线 API）
- get_shop_service_info(shop_id, topic)
- list_my_orders(status, time_range, cursor)
- get_my_order(order_id)
- get_my_after_sales(order_id)
- get_order_care_advice(order_id)

用户身份、平台和鉴权由执行上下文注入，不作为模型可编辑参数。工具限制单次条数、字段白名单、超时；只读请求允许有界重试，写操作禁止盲重试。

### 返回契约（拟定）
统一包含 ok、code、data、trace_id、source、fetched_at、retryable；错误码至少区分 AUTH_REQUIRED、FORBIDDEN、NOT_FOUND、AMBIGUOUS、UPSTREAM_TIMEOUT、UNSUPPORTED、STATE_CONFLICT。不得把堆栈、密钥或完整数据库错误返回模型/前端。

### H5 对话组件
- 店铺咨询卡、订单候选卡、订单状态卡、售后进度卡、登录续办提示。
- 当前只读卡不显示未接通的办理按钮；按钮能力由后端状态/权限决定。
- 显示数据查询时间；失败有重试；切换会话或账号时不回填旧请求。
- 语音提炼真实主要信息，不读全地址/手机号/订单号，不自动播报敏感详情。

### 持久化和并发
- agent 保存必要会话引用，订单/售后事实仍以业务后端为准，不复制为永久“事实记忆”。
- 需要映射、审计、待确认操作等新表时另写幂等迁移 SQL；表结构需在 P0 评审后定稿。
- 缓存按平台+用户+店铺+资源隔离；状态查询缓存短时有效，退款结果不可长期缓存。

## 5. 分阶段执行清单

| 阶段 | 工作与产物 | 验收门槛/依赖 |
|---|---|---|
| P0 基线审计 | 实际接口/字段/权限矩阵；梳理 guest、注册账号、微信账号映射；记录部署提交 | 业务接口归属检查完成，测试账号可用；缺口明确登记 |
| P1 身份与适配层 | 可信上下文、只读业务客户端、错误契约、追踪 ID | 伪造用户/订单、过期授权、跨平台访问均拒绝 |
| P2 店铺咨询 | 店铺规则数据、工具路由、咨询卡 | 锁店、多店澄清、规则缺失、接口故障场景通过 |
| P3 订单/售后只读 | 订单选择、详情、履约和退款进度、登录续办 | 多订单不误选、退款状态不混淆、无跨用户泄露 |
| P4 交互与语音 | 对话内卡片、摘要、重试、账号/会话切换清理 | 手机窄屏可操作、过时响应不串会话、语音不泄露私密字段 |
| P5 发布验收 | 回归报告、监控看板、迁移/配置/回滚、更新包清单 | 所有首版硬门槛通过后发布 1.4.0 + H5 1.1.0 |

暂不承诺固定工期；P0 后按真实接口缺口估算，不把外部商家接口、测试账号或域名准备计作已完成。

## 6. 测试矩阵与发布门槛

- 权限：匿名、合法账号、错误签名、过期、A 查 B 单、切换账号、平台隔离。
- 店铺：明确店铺/无店铺、多店、缺营业字段、配送边界、休息日、资料过期。
- 订单：无订单、唯一/多笔、分页、状态变更、配送/自提、已取消、已退款。
- 售后：无申请、待审、拒绝、已批准未退款、部分退款、退款失败/成功。
- 鲁棒性：超时、429、5xx、字段缺失、重复点击、断流、刷新、跨会话响应。
- 既有回归：DIY 修改/恢复、图片复用、贺卡订单、语音开关不得回退。

单元与接口测试使用隔离数据；真实模型场景另记成本和次数。生产验收只用专门测试账号/订单，不操作客户真实订单。查询结果必须与业务 API 核对。上线前所有权限/状态一致性用例通过；实体手机/微信未验收则明确阻断相应能力，不虚报完整可用。

## 7. 监控、灰度和回滚

按业务类型记录请求成功/失败、授权失败、工具耗时、上游错误、业务未完成原因；日志用 trace_id 关联，敏感信息脱敏，不记录 token 和全地址。完成率不能只算 HTTP 200。

新增能力默认关闭，先按测试账号/平台开启。后端先兼容部署，再发 H5；开关关闭后已有选花、DIY 和贺卡流程仍可运行。灰度出现越权、错误订单状态、旧流程严重回归立即关闭新能力并回滚应用。
