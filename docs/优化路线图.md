## 二、优化点（按 ROI 排序）

### ① 工具集按角色裁剪 —— 安全 + 性能双收益【最高优先级】

**现状**：C 端 `/chat` 的 LLM 经 `agent/agent.py:279` 的 `to_openai_tools()` 拿到**全部 21 个工具**，其中 **8 个是平台接入/运维工具**：

```
platform_db_discover          platform_mapping_draft
platform_db_test_connection   platform_mapping_save_draft
platform_db_sample_table      platform_mapping_list_drafts
                              platform_mapping_set_status
                              platform_mapping_get_active
```

目前**仅靠 prompt 里一句软约束**兜着（`agent.py:681`）：
> 「platform_db_discover / platform_db_sample_table / platform_mapping_*：部署接入期由配置方使用；日常对话不需要」

**风险与成本**：
- ⚠️ `platform_mapping_set_status` 可把映射改成 `active`/`revoked` —— 会话内 LLM 一旦被诱导（prompt injection）或误触发，就能改配置。软约束挡不住；
- 工具选择空间 21 → 越大越易选错；
- schema 多出约 1/3 体积。

**建议**：默认只给 C 端 **13 个**工具；运维工具加 env 开关（如 `ENABLE_OPS_TOOLS=false`），仅在接入期打开。

---

### ② 删除 prompt 内「工具说明书」段【高性价比】

`toolkit.generate_tool_manual()` 输出 3,970 字符（name + params + description），与 function-calling 的 `tools` 定义**内容完全重复**。
删除后：system 10,334 → **~6,364 字符（-38%）**，每轮总输入约 **-19%**。

---

### ③ 精简 `platform_db_query_entity` 描述【中】

810 字符（全库最长），把「营业状态字段 / 配送字段 / 跨店规则」等细节移到 prompt 场景 6，描述压到 ~300 字符。

---

### ④ 补自动化测试【治本】

近期 4 个线上问题**全部是回归/边界类**，且都靠人工端到端才发现：

| 编号 | 问题 | 类型 |
|---|---|---|
| I-1 | `shop_id='default'` 锁死会话 | 边界值 |
| I-2 | 回复出现 `---` 分隔线 | 格式回归 |
| H-1 | 生图补调死循环烧 API | 幂等缺失 |
| J-1 | 生图任务被临时循环取消 | 异步生命周期 |

建议 pytest 覆盖：**工具注册完整性**、prompt 关键段存在性、`normalize_*` 系列、生图任务生命周期、限流边界。有了这些，"修好又坏"的概率大幅下降。

---

### ⑤ prompt 外置为模板【中】

`_build_system` ~190 行硬编码字符串 → `agent/prompts/*.md`，便于迭代、版本化、A/B 对比。

### ⑥ 其他

- **长对话摘要压缩**：当前仅取最近 `HISTORY_LIMIT=20` 条消息，超长对话的早期信息会丢（长期记忆有部分兜底）；
- **L3 用户画像收敛**：`get_user_profile` / `save_user_profile` 工具已有，缺「冲突覆盖」策略。
