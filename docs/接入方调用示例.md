# 接入方调用示例（flora 智能体 API）

> 本文档给**想接入 flora 智能体的后端工程师**看，照抄即可跑通。
> 域名：`https://api.tiaowulan.com`（接口挂在根路径下，不是 `/v1/...`）。
> **这不是 OpenAI 兼容接口**，返回的是结构化 `ChatResponse`，不能用通用 OpenAI SDK 模板。

---

## ⚠️ 三个最常见误判（你大概率刚踩过）

| 你探测的地址 | 返回 | 真相 |
|---|---|---|
| `GET https://api.tiaowulan.com/` | 404 | 根路径没有 handler，**正常**，不是服务挂了 |
| `POST https://api.tiaowulan.com/v1/chat/completions` | 404 | 这是 OpenAI 风格路径，我们用 `/chat`，**不支持该路径** |
| `POST https://api.tiaowulan.com/chat` | 401「需要 Bearer 登录凭证」 | **正常且正确**——说明 `/chat` 活着，只是你还没登录 |

**关键点：光拿 `X-API-Key` 不能直接调 `/chat`。必须先用 Key 去 `/auth/token` 换一个 Bearer token，再用 token 调 `/chat`。**

---

## 标准调用流程（两步）

### 第 1 步：用 X-API-Key 换 Bearer token

```bash
curl -X POST https://api.tiaowulan.com/auth/token \
  -H "X-API-Key: <你的平台密钥>" \
  -H "Content-Type: application/json" \
  -d '{"external_user_id": "user_888"}'
```

返回：

```json
{
  "access_token": "eyJhbGciOi...（JWT，很长）",
  "token_type": "bearer",
  "user_id": "s001_a1b2c3d4e5f6...",
  "platform_id": "s001"
}
```

> 记下两样东西，下一步必须原样用：
> - `access_token` → 放进 `Authorization: Bearer <access_token>`
> - `user_id` → 放进 `/chat` 请求体的 `user_id` 字段（**必须和 token 里的一致**，否则 401）

### 第 2 步：带 token 调 /chat

```bash
curl -X POST https://api.tiaowulan.com/chat \
  -H "Authorization: Bearer <上一步的 access_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "s001_a1b2c3d4e5f6...",
    "message": "我想送花给女朋友，预算300",
    "session_id": ""
  }'
```

---

## 请求体字段（/chat）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `user_id` | string | ✅ | **必须是 `/auth/token` 返回的 `user_id`**，不能自己编造 |
| `message` | string | ✅ | 用户说的话 |
| `session_id` | string | ❌ | 多轮对话时传上一次返回的 `session_id`；首轮留空 `""` |
| `location` | object | ❌ | `{ "lat": 22.55, "lng": 114.06 }`，传了才能按距离推店 |
| `shop_id` | string | ❌ | **只从商品详情页/店铺页进入才传**（锁店）；其余入口不传 |
| `entry` | string | ❌ | `product` / `shop` / `home`，不传自动推断 |
| `product_id` | string | ❌ | 商品详情页进入时传 |
| `product_title` | string | ❌ | 商品详情页进入时传 |

> `shop_id` 传值规则见《小程序接入待办清单.md》第 5 节：**只有锁定了商品/店铺的入口才传**，首页/搜索/分类等未选定任何商品或店铺的入口**一律不传**（别传 `"default"` 占位字符串）。

## 响应体字段（ChatResponse）

```json
{
  "user_id": "s001_a1b2c3d4e5f6...",
  "reply": "送女朋友的话，11朵红玫瑰很经典～",   // ← 回复文本在这里
  "ui": "text",                                  // ← 渲染类型，决定怎么画 data
  "data": {},                                    // ← 卡片数据（见下表）
  "action": { "type": "none", "payload": {}, "required_capabilities": [], "fallback": "" },
  "tool_calls": [],                              // ← 本次调用的工具记录（调试用）
  "session_id": "a1b2c3...",                     // ← 多轮对话回传这个
  "stage": "analyze",
  "products": []                                 // ← 推荐商品数组
}
```

### `ui` 取值与 `data` 结构

| `ui` 值 | 含义 | `data` 结构 |
|---|---|---|
| `text` | 纯文字 | `{}` |
| `plan_card` | DIY 方案卡 | `{ "plans": [ ... ] }` |
| `shop_card` | 店铺推荐卡 | `{ "shops": [ ... ] }` |
| `order_card` | 下单卡 | `{ ... }` |
| `image_task` | 生图任务 | 同步完成给 `result_url`，异步给轮询信息 |
| `greeting_card` | 电子贺卡 | `{ "image_url": "..." }` |

> **图片和推荐卡片都在 `data` 里**，不在 `reply`。`reply` 永远是人类可读的文字说明。

## 流式模式（可选）

需要打字机效果用 SSE：

```bash
curl -N -X POST https://api.tiaowulan.com/chat/stream \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"user_id":"s001_a1b2c3d4e5f6...","message":"推荐一家附近的花店"}'
```

> ⚠️ **代理层必须关 SSE 缓冲**：`proxy_buffering off; gzip off; proxy_read_timeout 300s;`，否则前端收不到流。
> 小程序**不要直连** api.tiaowulan.com，走你们自己后端域名转发（全流量代理）。

## Windows cmd 用户注意

cmd.exe 不认单引号。JSON 数据请改用文件法：

```cmd
curl -X POST https://api.tiaowulan.com/chat ^
  -H "Authorization: Bearer <token>" ^
  -H "Content-Type: application/json" ^
  -d @body.json
```

`body.json`（UTF-8 保存）：
```json
{"user_id":"s001_a1b2c3d4e5f6...","message":"我想送花给女朋友","session_id":""}
```
