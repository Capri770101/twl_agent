## 部署验收

1. `docker compose config --quiet`、镜像构建与启动通过。
2. `/health` 返回 `{"status":"ok"}`；它不返回版本或 env，也不证明模型余额可用。
3. 内部 PostgreSQL 初始化、已有数据升级、监控表写入与聚合实际通过。
4. 宿主服务端平台 Key 换 JWT；后续请求 `user_id` 必须与 token 身份一致。
5. 缺/错凭证、他人会话、他人任务均不能访问；记录真实状态码和结果。
6. 数据源授权、只读连接/REST、店铺映射与真实商品结果核对。

## 业务验收矩阵

| 场景 | 必查结果 |
|---|---|
| 问答/推荐 | 有实质回答，商品事实来自已授权数据源，错误不伪装无商品 |
| 多轮会话 | 回传 session_id 后上下文连续，跨用户隔离 |
| DIY 修订 | 只改配色/包装不擅改花材数量，预算约束与修改授权匹配 |
| 版本恢复 | plans 接口正确，恢复后继续创建新版本，父版本和并发冲突处理正确 |
| 图片 | 新方案/修订图绑定正确，重复请求复用，失败重试，乱序完成不覆盖当前版 |
| 贺卡 | draft 可编辑，render 返回任务，done 后可下载且中文清晰 |
| 语音 | ASR/TTS 实际可用、内容摘要正确、缓存行为与监控口径一致 |
| 前端 | 流式分块、刷新恢复、网络中断、账号/会话切换不串数据 |

任务成功终态是 `done`；`failed/not_found` 应停止轮询。以实际 `result_url` 展示，不自行猜文件名或硬编码历史域名。效果图视觉质量需要人工确认，接口成功不代表画面符合全部花材和支数。

## 客户服务候选验收

按照 [HANDOFF-CHECKLIST](../releases/v1.4.0/HANDOFF-CHECKLIST.md) 使用专用测试客户和订单，覆盖票据签名/过期、A 查 B、退出或切账号、分页、售后状态、真实模型工具选择。与商家后台逐条核对；审核通过不能说成退款到账。

新功能默认关闭；受控响应/离线测试不是“真实商家接口验收”。新身份不会自动迁移旧历史，需明确产品策略。

## 监控验收

`/api/metrics/*` 支持 `X-Dashboard-Key`、Bearer 或 SSE 的 `?key=`；缺配置 503，错凭证 401。检查 summary/calls/platforms/tools/speech/images/customer-service/stream。客户服务成功率只表示查询结果，不代表订单办理完成。
